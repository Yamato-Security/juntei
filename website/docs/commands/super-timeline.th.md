# ซุปเปอร์ไทม์ไลน์ { #super-timeline }

`super-timeline` เปลี่ยนสิ่งที่แยกวิเคราะห์ให้เป็นเหตุการณ์ที่มีสคีมาทั่วไปและจัดเรียงตามเวลา เร็กคอร์ด Prefetch สามารถมีเวลาดำเนินการได้หลายครั้ง บันทึก MFT สามารถมีการประทับเวลาไฟล์ได้แปดรายการขึ้นไป แต่ละกิจกรรมจะกลายเป็นกิจกรรมที่มีป้ายกำกับแยกกัน ทำให้ง่ายต่อการเปรียบเทียบหลักฐานจากแหล่งต่างๆ โดยไม่สูญเสียความหมายของการประทับเวลาแต่ละรายการ

เริ่มต้นด้วยผลลัพธ์ของ [`auto-parse`](auto-parse.md) แทนที่จะเป็นไดเร็กทอรีหลักฐานดั้งเดิม:

```bash
juntei auto-parse -d evidence/ -o parsed/
juntei super-timeline -d parsed/ -o SuperTimeline.csv
```

เก็บไฟล์ที่แยกวิเคราะห์ รายการ และหลักฐานต้นฉบับไว้ เส้นเวลาเป็นการฉายภาพเพื่อการวิเคราะห์ มันไม่ได้แทนที่บันทึกเหล่านั้นหรือสร้างไฟล์พื้นที่เก็บข้อมูล Plaso ดั้งเดิม

## การใช้งาน { #usage }

```bash
# Native CSV (default)
juntei super-timeline -d parsed/ -o SuperTimeline.csv

# Native JSON Lines
juntei super-timeline -d parsed/ -o SuperTimeline.jsonl -t jsonl

# Combine native records and an existing Hayabusa JSONL timeline
juntei super-timeline -f NativeRecords.jsonl --hayabusa Hayabusa.jsonl \
  -o SuperTimeline.jsonl -t jsonl

# Timesketch import profile; also available with CSV
juntei super-timeline -d parsed/ -o Timesketch.jsonl -t jsonl --profile timesketch

# One standalone CSV needs an artifact identifier and, if unavailable, a computer name
juntei super-timeline -f MFT.csv --input-artifact mft --computer HOST01 \
  -o Host01Timeline.csv

# Reduce the time range, memory used by sorting, or number of workers
juntei super-timeline -d parsed/ -o IncidentTimeline.jsonl -t jsonl \
  --timeline-start "2026-10-20T06:00:00Z" --timeline-end "2026-10-20T14:00:00Z" \
  --memory-limit 64 -T 4 --temp-dir scratch/
```

`--hayabusa FILE` สามารถทำซ้ำหรือใช้เดี่ยวๆ ได้ โดยนำเข้าการประทับเวลาเหตุการณ์/การแจ้งเตือนและบริบทของกฎที่มีอยู่โดยไม่ต้องเรียกใช้ Hayabusa เหตุการณ์ที่ให้ข้อมูลซึ่ง `Details` เป็นสตริงได้รับการสนับสนุน `--artifact mft,prefetch` จำกัดการฉายภาพสำหรับตัวระบุส่วนที่เลือก รวมการจำกัดเวลาและต้องมีออฟเซ็ต UTC หรือ `Z` ที่ชัดเจน

### การเลือกอินพุต { #choosing-an-input }

| อินพุต | มันถูกระบุอย่างไร |
|---|---|
| `-d DIR` | `manifest.json` จัดหางานหลัก รหัสสิ่งประดิษฐ์ คอมพิวเตอร์ และไฟล์เอาท์พุตที่แน่นอนให้สำเร็จ งาน `auto-parse -j` รองจะถูกแยกออก เพื่อป้องกันการอิมพอร์ตทั้งสองสำเนา |
| `-f FILE` | JSON/JSONL แบบเนทีฟใช้ฟิลด์ `Artifact` และ `Comp` แบบฝัง การส่งออกที่ไม่ได้ติดแท็กจำเป็นต้องมี `--input-artifact`; CSV แบบสแตนด์อโลนต้องการมันเสมอ |
| `--computer NAME` | ทางเลือกสำรองเมื่อบันทึกอินพุตไม่มีชื่อคอมพิวเตอร์ ไม่เช่นนั้นคอมพิวเตอร์ที่ไม่รู้จักจะเป็น `Unknown` อย่างชัดเจน |
| `--hayabusa FILE` | JSONL พร้อมการประทับเวลา Hayabusa, ข้อมูลเมตาของกฎ, คอมพิวเตอร์ และ `EvtxFile` หากมี |

รายการปัจจุบันสนับสนุนการย้ายตำแหน่งของไดเร็กทอรีที่แยกวิเคราะห์: เส้นทางเอาต์พุตสัมบูรณ์ที่บันทึกไว้ได้รับการแก้ไขภายใต้ไดเร็กทอรีใหม่ อินพุตจะต้องคงอยู่ภายใน รวมถึงเป้าหมายลิงก์สัญลักษณ์ด้วย รองรับไดเร็กทอรีต่ออาร์ติแฟกต์ Amcache, SRUM และ Jump Lists แบบเดิม ไดเร็กทอรีหมวดหมู่ต้องมี `OutputFiles` ที่ชัดเจน

รองรับไฟล์ Manifest ปัจจุบันที่มีเส้นทางสัมพันธ์กับเอาต์พุตและการส่งออกหลายตารางแบบแยกส่วนได้รับการสนับสนุน คำสั่งจดจำทุกสิ่งประดิษฐ์ที่กำหนดเวลาโดยการแยกวิเคราะห์อัตโนมัติ รวมถึงเบราว์เซอร์รุ่นใหม่ ตาราง WebCache, Outlook และ UAL

เมื่อไฟล์ Manifest ระบุรูปภาพ VHDX หรือ E01 การอ้างอิงแหล่งที่มาจะรวมรูปภาพและเส้นทางภายใน และชื่อรูปภาพจะยังคงอยู่ในบริบทของเหตุการณ์ ไม่จำเป็นต้องมีพื้นที่ทำงานชั่วคราวในการอ่านผลลัพธ์ที่แยกวิเคราะห์

แหล่งที่มาดิบถูกนำมาจากเรกคอร์ดหรือคำสั่งรายการที่ชัดเจน ด้วย `-d` การอ้างอิงแหล่งข้อมูลดิบจะสัมพันธ์กับไดเร็กทอรีหลักฐาน และ `Details.ParsedFile` และ `InputFiles` สรุปจะสัมพันธ์กับไดเร็กทอรีที่แยกวิเคราะห์ ชื่อเอาต์พุตสรุป/รายงานสัมพันธ์กับไดเร็กทอรีเอาต์พุตของไทม์ไลน์ ตาราง SRUM CSV ถูกกำหนดให้กับฐานข้อมูลเฉพาะเมื่อโฮสต์มี SRUDB.dat ที่รวบรวมไว้ซึ่งสามารถระบุตัวตนได้หนึ่งรายการเท่านั้น มิฉะนั้น `SourceFile` จะชี้ไปที่ไฟล์ที่แยกวิเคราะห์ และ `Details.RawSourceAvailable` คือ `false`

อินพุตแบบสแตนด์อโลนถูกอ้างอิงโดยชื่อไฟล์ อินพุตที่มีชื่อไฟล์เดียวกันจะใช้การอ้างอิง `./Inputs/<ID>/<filename>` ที่แตกต่างกัน เส้นทางแหล่งดิบสัมบูรณ์ที่อยู่นอกรากหลักฐานที่ทราบจะใช้ตัวระบุ `./Sources/<ID>/<filename>` การอ้างอิงที่ทึบแสงเหล่านี้ยังคงรักษาความแตกต่างของแหล่งที่มาโดยไม่ต้องส่งออกชื่อไดเร็กทอรีที่แน่นอนของนักวิเคราะห์ ศึกษาบันทึกดั้งเดิมโดยใช้ `ParsedFile` และ `InputRecord` สำหรับต้นฉบับ เส้นทางที่บันทึกไว้ในหลักฐาน เช่น เส้นทางปฏิบัติการ Windows ยังคงไม่เปลี่ยนแปลง

## ฟิลด์เหตุการณ์ทั่วไป { #common-event-fields }

| สนาม | ความหมาย |
|---|---|
| `Timestamp` | UTC RFC 3339 เขียนด้วยเศษส่วนเก้าหลักเพื่อการเรียงลำดับที่สอดคล้องกัน การแพดดิ้งไม่ได้เพิ่มความแม่นยำ |
| `Comp` | คอมพิวเตอร์ที่เกี่ยวข้องกับบันทึกอินพุต |
| `Artifact` | ตัวระบุวัตถุที่เสถียร เช่น `mft`, `prefetch`, `srum` หรือ `hayabusa` |
| `TimestampType` | คำอธิบายความหมายของการประทับเวลา เช่น `MFT SI Data modified` |
| `User` | บัญชีที่บันทึกไว้หรือ SID เมื่ออะแดปเตอร์มี อาจจะว่างเปล่า |
| `Path` | ไฟล์ คีย์รีจิสทรี หรือวัตถุเฉพาะอื่นๆ ที่ได้รับผลกระทบ |
| `Message` | คำอธิบายสั้น ๆ สำหรับผู้ดูไทม์ไลน์ |
| `SourceFile` | การอ้างอิงแหล่งที่มาดิบโดยอิงตามหลักฐาน หรือตัวระบุแหล่งที่มาแบบสัมพันธ์เมื่อไม่ทราบราก มิฉะนั้นทางเลือกไฟล์แยกวิเคราะห์ที่อธิบายไว้ข้างต้น |
| `SourceField` | ช่องแยกวิเคราะห์ที่แน่นอนหรือตำแหน่งที่ซ้อนกันที่ใช้สำหรับการประทับเวลา |
| `RecordID` | ข้อมูลระบุตัวตนของบันทึกเฉพาะอาร์ติแฟกต์ ไม่จำเป็นต้องเป็น EVTX Record ID |
| `Details` | บริบทที่มีโครงสร้างรวมถึงการประทับเวลาดั้งเดิม ความแม่นยำ พื้นฐานเวลา บทบาทเวลา ไฟล์ที่แยกวิเคราะห์ บันทึกอินพุต/ตำแหน่ง และเมตาดาต้าการกู้คืน/กฎที่มีอยู่ |

ใน CSV `Details` คือเซลล์ JSON ที่มีเครื่องหมายคำพูด ใน JSONL มันเป็นอ็อบเจ็กต์ โปรไฟล์ Timesketch จะเปลี่ยน `Timestamp`, `TimestampType` และ `Message` เป็น `datetime`, `timestamp_desc` และ `message` ตามลำดับ โดยที่ยังคงรักษาฟิลด์แหล่งที่มาอื่นๆ ไว้ สิ่งเหล่านี้คือ [ ฟิลด์นำเข้า Timesketch ที่จำเป็นสามฟิลด์](https://timesketch.org/guides/user/import-from-json-csv/)

`Details` จงใจมีบริบทที่เลือก แทนที่จะเป็นข้อมูลไบนารีแบบเต็มหรือฟิลด์บันทึกเนทิฟทุกช่อง สตริง อาร์เรย์ และอ็อบเจ็กต์แบบยาวถูกผูกไว้และทำเครื่องหมาย `ProjectionOmitted` ค้นหา `Details.ParsedFile`, `InputRecord` และ `Location` เพื่อตรวจสอบบันทึกเนทิฟที่สมบูรณ์ สำหรับ CSV หมายเลขบันทึกจะนับบันทึก CSV หลังส่วนหัว ไม่ใช่เส้นฟิสิคัลภายในเซลล์ที่ยกมา สำหรับ JSONL จะเป็นหมายเลขบรรทัด สำหรับ JSON เป็นหมายเลขเอกสารระดับบนสุดบวกกับตำแหน่งที่ซ้อนกัน

## เวลาหมายถึงอะไร { #what-the-times-mean }

การประทับเวลาเป็นหลักฐานเกี่ยวกับวัตถุที่บันทึกไว้ ไม่ใช่หลักฐานการประหารชีวิตหรือการโจมตีโดยตัวมันเอง อะแดปเตอร์มีเจตนาที่จะรักษาความแตกต่างเหล่านี้:

| สิ่งประดิษฐ์ | การตีความไทม์ไลน์ |
|---|---|
| MFT | แยกการแก้ไข SI และ FN การเข้าถึง การเปลี่ยนแปลงข้อมูลเมตา และเวลาการสร้าง แอ็ตทริบิวต์ FN ที่มีชื่อยังคงแตกต่างกัน ฟิลด์ SI ที่ซ้ำกันในแถวชื่อไฟล์จะถูกรวมเข้าด้วยกัน ไม่รวมเวลาไฟล์ฐานที่ใช้ร่วมกันของแถว ADS ชื่อ slack ของบันทึก FILE ที่กู้คืนแล้ว จะเก็บเหตุการณ์ FN ที่กู้คืนแยกกัน |
| I30 | จัดเก็บข้อมูลเมตา FN/ดัชนี พร้อมบริบทการหย่อน/การกู้คืนเมื่อพร้อมใช้งาน สิ่งเหล่านี้ไม่ใช่การประทับเวลาของการเขียนดัชนีไดเร็กทอรี |
| USN วารสาร | การประทับเวลาบันทึกบันทึกประจำวันและเหตุผลในการอัปเดต บันทึกสามารถอธิบายการเปลี่ยนแปลงได้หลายอย่าง ไม่จำเป็นต้องบันทึกเวลาเริ่มต้นที่แน่นอน |
| LogFile | จัดเก็บสแนปชอตการประทับเวลาซ้ำ/เลิกทำและข้อมูลเมตาของชื่อไฟล์ ทำซ้ำและเลิกทำโดยแยกจากกัน LSN และออฟเซ็ตไฟล์เป็นตัวระบุ ไม่เคยแปลงเป็นวันที่ |
| Prefetch | เวลาดำเนินการที่บันทึกไว้ รวมกับการส่งออกไทม์ไลน์ Prefetch ที่ตรงกัน ข้อมูลเมตาการสร้างวอลุ่มอ้างอิงมีป้ายกำกับแยกกัน |
| เบราว์เซอร์ฐานข้อมูล SQLite | การเข้าชมที่บันทึกไว้ ข้อมูลเมตาการเข้าชมครั้งล่าสุดที่กู้คืน การเริ่มต้น/สิ้นสุดการดาวน์โหลด การสร้างคุกกี้/การเข้าถึง/หมดอายุ และประวัติการใช้ครั้งแรก/ครั้งสุดท้ายหรือการลบหลุมฝังศพ การสิ้นสุดการดาวน์โหลดไม่ได้พิสูจน์ความสำเร็จหรือการดำเนินการด้วยตนเอง การหมดอายุของคุกกี้คือกำหนดเวลาที่กำหนดไว้ สถานะการฟื้นตัว ความเชื่อมั่น และต้นกำเนิดยังคงอยู่ในบริบท |
| Internet Explorer / Edge รุ่นเก่า WebCache | การเข้าถึงรายการที่จัดเก็บ การสร้าง/การแก้ไข การหมดอายุและการซิงโครไนซ์ การเริ่มดาวน์โหลด ข้อมูลเมตาของคุกกี้ และการเข้าถึง/การกำจัดคอนเทนเนอร์ การทำบัญชีด้วยแคชไม่ใช่หลักฐานโดยอัตโนมัติว่าผู้ใช้เปิดเพจ |
| Outlook PST, OST, MSG และ OFT | การส่ง/ส่งข้อความ; การสร้าง/แก้ไขโฟลเดอร์ รายการ และไฟล์แนบ เริ่มต้น/สิ้นสุด/เตือนปฏิทิน; งานเริ่ม/ครบกำหนด/เสร็จสิ้น/เตือนความจำ; และพิมพ์คุณสมบัติเวลาอย่างชัดเจน เวลาที่กำหนดเวลาไว้ไม่ได้พิสูจน์ว่ามีการประชุมเกิดขึ้น มีการแจ้งเตือนเกิดขึ้น หรือมีการดำเนินการตามโปรแกรม เวลาจัดส่งที่เก็บไว้ไม่ได้พิสูจน์ว่าได้อ่านข้อความแล้ว |
| การบันทึกการเข้าถึงของผู้ใช้ (UAL) | เมตาดาต้าการเข้าถึงครั้งแรก/ครั้งสุดท้าย การแทรก/การสร้างฐานข้อมูล เวลาบูตระบบปฏิบัติการที่เห็นครั้งแรก/ครั้งสุดท้าย และที่จัดเก็บไว้ บทบาท บัญชี ที่อยู่ต้นทาง และตัวนับรายวันยังคงมีบริบทอยู่ วันที่/การนับรายวันไม่ได้เกิดจากการเข้าสู่ระบบตอนเที่ยงคืน ข้อมูลประจำตัวที่ยังไม่กำหนดเวลาและแถว DNS ยังคงมีอยู่ในรายงานที่แสดงร่วม |

### ความแม่นยำ เวลาท้องถิ่น และสมมติฐาน { #precision-local-times-and-assumptions }

ฟิลด์ UTC ที่รู้จักและการประทับเวลาที่มีการออฟเซ็ตที่ชัดเจนจะถูกทำให้เป็นมาตรฐานเป็น UTC ค่าดั้งเดิมและความแม่นยำที่บันทึกไว้จะยังคงอยู่ รวมถึง 100 ns FILETIMEs ตัวแยกวิเคราะห์ต้นทางหรือวิวเวอร์ดาวน์สตรีมอาจปัดเศษเวลาแล้ว คำสั่งนี้ไม่สามารถเรียกคืนความแม่นยำที่สูญเสียไป

ฟิลด์เชลล์ไอเท็ม/FAT บางฟิลด์มีความหมายตามเวลาท้องถิ่น แม้ว่าตัวแยกวิเคราะห์อัปสตรีมจะทำให้ซีเรียลไลซ์ฟิลด์เหล่านั้นด้วย `Z` ก็ตาม เส้นเวลาจะรักษาค่าที่แยกวิเคราะห์และที่มาของฟิลด์ ไม่สามารถกู้คืนเขตเวลาปลายทางที่ขาดหายไปหรือตรวจสอบการแปลงอัปสตรีมได้ ตรวจสอบอาร์ติแฟกต์ดิบและการตั้งค่าตำแหน่งข้อมูลก่อนที่จะใช้เวลาดังกล่าวเพื่อสร้างความสัมพันธ์ข้ามโฮสต์ที่แม่นยำ

การประทับเวลาไร้เดียงสาที่ไม่มีโซนเวลาที่กำหนดโดยสิ่งประดิษฐ์ได้รับการวินิจฉัย แทนที่จะถือว่าเป็น UTC โดยไม่แจ้งให้ทราบ หากหลักฐานพิสูจน์ได้ ให้ระบุค่าชดเชยคงที่ที่ลงนามแล้ว:

```bash
juntei super-timeline -f Amcache.jsonl --input-artifact amcache \
  --assume-offset "+09:00" -o Timeline.csv
```

ค่าเฉพาะวันที่จำเป็นต้องมีตัวเลือกนั้นด้วย สมอเที่ยงคืนของพวกเขามีป้ายกำกับว่าเป็นสมมติฐานที่มี **ความแม่นยำของวัน**; ไม่ใช่เหตุการณ์เที่ยงคืนที่สังเกตได้ ไม่ยอมรับชื่อเขตเวลาและกฎการปรับเวลาตามฤดูกาล ค่าที่หายไป เป็นศูนย์ ไม่ถูกต้อง และอยู่นอกช่วงจะไม่สร้างเหตุการณ์ยุคสังเคราะห์ วันที่ 1970 ที่ถูกต้องที่บันทึกไว้อย่างชัดเจนจะถูกเก็บไว้

หมวดหมู่ที่ไม่บังคับสองหมวดหมู่จะถูกยกเว้นตามค่าเริ่มต้น:

- `--include-collection-times`: LNK/Jump List ข้อมูลเมตาของไฟล์ต้นฉบับบนระบบไฟล์การรวบรวม/การวิเคราะห์ เหตุการณ์เหล่านี้มีชื่อว่า `collection_filesystem` ซึ่งแยกจากกิจกรรมปลายทาง
- `--include-interpreted-times`: ค่า QWORD ของรีจิสทรีทั่วไปที่แสดงผลเป็น FILETIME โดยตัวอ่านรีจิสทรี มีป้ายกำกับว่า `interpreted_value` เนื่องจากค่าดังกล่าวจำนวนมากเป็นตัวนับจริงๆ

## รายงานสหาย { #companion-reports }

สำหรับ `SuperTimeline.csv` คำสั่งยังเขียน:

- `SuperTimeline.csv-Untimed.jsonl`: ตำแหน่งบันทึกดั้งเดิมโดยไม่มีการประทับเวลาเหตุการณ์ที่แมปที่ใช้งานได้
- `SuperTimeline.csv-Diagnostics.jsonl`: เวลาที่ไม่ถูกต้อง/คลุมเครือ ตั้งใจข้ามข้อมูลเมตาที่แชร์และข้อจำกัดด้านความเที่ยงตรงที่ต้องใช้บันทึกแยกวิเคราะห์ต้นฉบับ
- `SuperTimeline.csv-Summary.json`: ไฟล์อินพุต, จำนวนต่อสิ่งประดิษฐ์, เหตุการณ์ที่กรอง/ผู้สมัคร/รวม, จำนวนเอาต์พุต, ผู้ปฏิบัติงาน, จัดเรียงงบประมาณ/ชิ้น/บัตรผ่าน และเวลาที่ผ่านไป

ชื่อร่วมประกอบด้วยชื่อไฟล์เอาต์พุตที่สมบูรณ์ ตัวอย่างเช่น `SuperTimeline.jsonl` มี `SuperTimeline.jsonl-Summary.json` ของตัวเองและมีรายงานที่ยังไม่กำหนดเวลา/การวินิจฉัยที่เกี่ยวข้อง การส่งออก CSV และ JSONL ที่มีต้นกำเนิดเดียวกันสามารถอยู่ร่วมกันได้ `-C` จำเป็นสำหรับการแทนที่ชุดผลลัพธ์ที่มีอยู่เท่านั้น

วันที่ที่ถูกต้องซึ่งกำลังรอการเพิ่มสมมติฐานเขตเวลาที่สมเหตุสมผล `UnresolvedTimeZones` แทนที่จะเป็น `InvalidTimestamps` ทั้งสองยังคงติดตามได้ในการวินิจฉัย ไม่มีการคิดค้นการประทับเวลา

บันทึกที่มีเวลาที่ถูกต้องนอกช่วงที่ร้องขอจะถูกนับว่ากรองแล้ว ไม่ใช่ไม่กำหนดเวลา จำนวนเหตุการณ์ผู้สมัครนำหน้าการรวมบัญชีที่ซ้ำกัน `Complete: true` หมายถึงอินพุตที่แยกวิเคราะห์ที่เลือกทั้งหมดได้รับการประมวลผลสำเร็จ ไม่ได้หมายความว่าทุกสิ่งประดิษฐ์ถูกรวบรวม ทุกสนามมีการประทับเวลา หรือทุกการโจมตีสามารถตรวจพบได้

การส่งออก CSV สามารถทำให้ข้อมูลเมตาที่ซ้อนกันเรียบลงได้: โปรไฟล์ข้อมูลระบบ จุดต่อเชื่อมผู้ใช้ USB รายการเชลล์ และบริบทที่มีโครงสร้างอื่นๆ สามารถมีความสมบูรณ์ยิ่งขึ้นใน JSON/JSONL ใช้อินพุตดั้งเดิมเมื่อช่องเหล่านั้นมีความสำคัญ ไทม์ไลน์ไม่สามารถสร้างข้อมูลที่ละเว้นโดยการส่งออก CSV ใหม่ได้ รหัสอาร์ติแฟกต์ที่ไม่รองรับและไฟล์อินพุตที่มีรูปแบบไม่ถูกต้องทำให้เกิดข้อผิดพลาดแทนที่จะเป็นผลลัพธ์บางส่วนที่สำเร็จ

## ประสิทธิภาพและความปลอดภัยของผลผลิต { #performance-and-output-safety }

อินพุตจะถูกสตรีมและประมวลผลแบบขนาน จัดเรียงบัฟเฟอร์สลิปไปยังไดเร็กทอรีชั่วคราวส่วนตัว จากนั้นการผสานแบบมีขอบเขตจะสร้างเอาต์พุตตามลำดับเวลาที่กำหนด การเรียงลำดับใช้วินาทีจำนวนเต็มและนาโนวินาที รวมถึงวันที่ก่อน 1970 การสั่งซื้อในเวลาเท่ากันนั้นถูกกำหนดตามจำนวนพนักงานและจัดเรียงงบประมาณ

`--memory-limit` เป็น **งบประมาณการเรียงลำดับบัฟเฟอร์** แบบรวม ไม่ใช่ขีดจำกัด RSS ของกระบวนการ บันทึกอินพุต, โอเวอร์เฮดอ็อบเจ็กต์/สตริง JSON, บัฟเฟอร์ CSV และบันทึกผสานต้องใช้หน่วยความจำเพิ่มเติม จำนวนพนักงานลดลงสำหรับงบประมาณเพียงเล็กน้อย `--max-record-size` จำกัดการบันทึกอินพุตที่แยกวิเคราะห์ (ค่าเริ่มต้น 16 MiB) อาร์เรย์/รายงาน JSON ที่สวยงามนับเป็นเอกสารอินพุตระดับบนสุดหนึ่งเอกสาร เอกสารขนาดใหญ่อาจต้องมีขีดจำกัดที่สูงกว่า หรือควรเป็น JSONL CSV parser แบบอ่านล่วงหน้ายังสนับสนุนขีดจำกัดนี้ด้วย

พื้นที่ดิสก์ชั่วคราวต้องรองรับกิจกรรมที่ขยายและบัตรผสาน นอกเหนือจากผลลัพธ์สุดท้าย เรกคอร์ดสามารถให้ผลลัพธ์ได้หลายเหตุการณ์ ดังนั้นไทม์ไลน์จึงอาจมีขนาดใหญ่กว่าอินพุตได้มาก กรองช่วงเวลา/อาร์ทิแฟกต์ตามความเหมาะสม และเลือกวอลุ่มชั่วคราวที่มีพื้นที่ว่างเพียงพอ

Ctrl+C ยกเลิกการทำงานร่วมกัน ลบไดเร็กทอรีการเรียงลำดับ/การแสดงละครส่วนตัว และออกด้วยโค้ด `130` บน Linux และ macOS สิ่งนี้ยังใช้กับ SIGTERM และ SIGHUP อีกด้วย มีการตรวจสอบการยกเลิกในขณะที่อ่าน ปรับมาตรฐาน รวม และเขียนรายงาน ก่อนที่จะเริ่มเผยแพร่ การเลิกจ้างที่ไม่สามารถตรวจจับได้หรือการสูญเสียพลังงานยังคงสามารถทิ้งไฟล์ชั่วคราวไว้ได้

การเขียนทับผลลัพธ์เดิมต้องใช้ `-C` ไทม์ไลน์และรายงานประกอบต้องไม่เขียนทับอินพุต แมนิเฟสต์ หรือหลักฐานและไดเรกทอรีที่ได้รับการป้องกัน ข้อผิดพลาดระหว่างอ่านหรือเรียงลำดับจะไม่เปลี่ยนผลลัพธ์เดิม ไฟล์ที่เสร็จแล้วจะเตรียมไว้ข้างปลายทางและแทนที่ทีละไฟล์ โดยเผยแพร่ไทม์ไลน์เป็นไฟล์สุดท้าย ขั้นตอนนี้**ไม่ใช่**ธุรกรรมเดียวสำหรับทั้งสี่ไฟล์ ความล้มเหลวของ I/O ช่วงสุดท้ายอาจเกิดหลังจากแทนที่รายงานประกอบบางไฟล์แล้ว ควรใช้ชื่อฐานใหม่ในแต่ละครั้งเพื่อเก็บผลลัพธ์เดิมที่สมบูรณ์ไว้

## ตัวแยกวิเคราะห์หลายตารางที่ใหม่กว่า { #newer-multi-table-parsers }

JSON/JSONL ดั้งเดิมมีชื่อตารางแต่ละชื่อ สำหรับ CSV แบบสแตนด์อโลน เบราว์เซอร์ WebCache และอะแดปเตอร์ Outlook จะระบุตารางจากสกีมาคอลัมน์ ดังนั้นการเปลี่ยนชื่อ CSV หรือใช้ส่วนต่อท้ายแหล่งที่มาของการแยกวิเคราะห์อัตโนมัติจะไม่เปลี่ยนการตีความการประทับเวลา UAL เก็บฟิลด์การประทับเวลาที่ชัดเจนไว้ ตัวนับการเข้าถึงและข้อความดูวันที่ที่ไม่เกี่ยวข้องจะไม่ถูกเดาว่าเป็นวันที่

แถวคุณสมบัติของ Outlook จะถูกฉายเฉพาะเมื่อประเภทที่ประกาศเป็นประเภทเวลาหรือหลายเวลาเท่านั้น สตริงที่มีวันที่ยังคงเป็นสตริง ข้อความที่ฝังไว้จะเก็บ ID รายการและการอ้างอิงพาเรนต์ และเวลาการแยกไฟล์แนบจะไม่แทนที่การประทับเวลาไฟล์แนบที่เก็บไว้ ไฟล์ ผู้รับ ผู้ติดต่อ หรือแถวคุณสมบัติที่ยังไม่กำหนดเวลายังคงติดตามได้ในเอาต์พุตดั้งเดิมและรายงานที่ไม่กำหนดเวลา

สกีมาเอาต์พุต CSV และ JSONL เดียวกันใช้กับ parsers เหล่านี้ การเพิ่มส่วนใหม่ไม่ได้เพิ่มคอลัมน์ CSV หลายร้อยคอลัมน์ บริบทเฉพาะของอาร์ติแฟกต์ยังคงอยู่ใน `Details`
