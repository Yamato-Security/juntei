# YARA स्कैन { #yara-scan }

पोर्टेबल Rust इंजन से एकत्रित फ़ाइलों की जाँच करें। Windows, macOS और Linux समर्थित हैं। फ़ाइलें केवल डेटा के रूप में पढ़ी जाती हैं, चलाई नहीं जातीं। यह कमांड स्वचालित आर्टिफ़ैक्ट पार्सिंग से अलग है।

## नियम चुनें { #choose-rules }

डिफ़ॉल्ट Core सटीकता और प्रदर्शन को प्राथमिकता देता है। Extended जाँच का दायरा बढ़ाता है। Full का दायरा सबसे व्यापक है, लेकिन गलत चेतावनियाँ अधिक हो सकती हैं।

```bash
juntei yara-scan -d evidence/ -o yara-core/
juntei yara-scan -d evidence/ --ruleset extended -o yara-extended/
juntei yara-scan -d evidence/ --ruleset full -o yara-full/ -t jsonl
juntei yara-scan -d evidence/ --rules local-rules/ -o yara-offline/
```

`--rules <FILE_OR_DIRECTORY>`: बिना डाउनलोड के स्थानीय UTF-8 नियम फ़ाइल या निर्देशिका इस्तेमाल करें। निर्देशिकाएँ पुनरावर्ती रूप से खोजी जाती हैं। include चुनी गई नियम निर्देशिका तक सीमित रहता है और निर्भरता क्रम में एक बार विस्तृत होता है। अमान्य या असमर्थित नियम चुपचाप हटाए नहीं जाते; संकलन रुक जाता है।

## सीमाएँ और दायरा { #limits-and-scope }

क्वारंटीन से निकाली गई सामग्री सहित सभी सामान्य फ़ाइलें पात्र हैं। प्रतीकात्मक लिंक और विशेष फ़ाइलें छोड़ दी जाती हैं। आर्काइव या डिस्क इमेज खोली नहीं जातीं और लाइव मेमोरी स्कैन नहीं होती। स्थिर, निकाली गई फ़ाइलें और साक्ष्य से बाहर नई आउटपुट निर्देशिका इस्तेमाल करें।

- `-T, --threads <N>`: समानांतर स्कैन की संख्या; डिफ़ॉल्ट CPU संख्या है, अधिकतम 8।
- `--timeout <SECONDS>`: प्रति फ़ाइल मूल्यांकन की समय-सीमा सेकंड में; डिफ़ॉल्ट 60।
- `--max-file-mib <MIB>`: वैकल्पिक अधिकतम फ़ाइल आकार MiB में; डिफ़ॉल्ट रूप से कोई सीमा नहीं। अलग विकल्प न देने पर MFT पर भी लागू। स्पष्ट सीमा से बड़ी फ़ाइलें छोड़ी गई के रूप में रिपोर्ट होती हैं।
- `--rules-release YYYYMMDD`: Forge रिलीज़ की तारीख या डिफ़ॉल्ट latest। जाँच दोहराने के लिए डाउनलोड किए गए स्रोत और हैश सहेजे जाते हैं।

## परिणाम { #results }

- `YaraDetections.csv` / `YaraDetections.jsonl`: नियम/फ़ाइल मिलान: सापेक्ष पथ, साक्ष्य कंप्यूटर नाम, हैश, मेटाडेटा और सीमित मिलान ऑफ़सेट। मिले हुए बाइट निर्यात नहीं होते।
- `YaraFiles.csv` / `YaraFiles.jsonl`: प्रति फ़ाइल कवरेज, जिसमें छोड़ी गई फ़ाइलें, पढ़ने की त्रुटियाँ, समय-सीमा और आंशिक परिणाम शामिल हैं।
- `Summary.json`: पूर्णता स्थिति, सेटिंग, गिनती, इंजन संस्करण और स्रोत हैश।
- `Rules.yar`: डाउनलोड किए गए सटीक नियम या विस्तृत स्थानीय नियमों का स्नैपशॉट।
- `CompilationWarnings.txt` / `CompilationError.txt`: संकलन चेतावनियाँ या संकलन विफल होने पर त्रुटि।

निकास कोड: 0 पूर्ण, 3 अधूरा कवरेज, 2 सेटअप/आउटपुट विफलता और 130 रद्द करना। मिलान जाँच का संकेत है, समझौते का प्रमाण नहीं; कोई मिलान न होना भी सुरक्षा का प्रमाण नहीं है। नियम का शीर्षक और आर्टिफ़ैक्ट का संदर्भ जाँचें। क्वारंटीन सामग्री पहचानने से पहले डिक्रिप्ट करें।

## MFT मिलान और पुनर्प्राप्ति { #mft-recovery }

MFT को कच्चे बाइट के रूप में एक-एक करके स्कैन किया जाता है और डिफ़ॉल्ट आकार सीमा नहीं है। मिलान स्थान के रिकॉर्ड पार्स होते हैं तथा उनके रेज़िडेंट DATA स्ट्रीम अलग से स्कैन होते हैं। केवल स्वतंत्र रूप से नियम से मिलने वाले स्ट्रीम पुनर्प्राप्त होते हैं। मेटाडेटा, कई रिकॉर्डों में फैले और नॉन-रेज़िडेंट मिलान सामग्री निर्यात किए बिना रिपोर्ट होते हैं।

`--max-file-mib <MIB>` → `--max-mft-mib <MIB>` · `--max-mft-recoveries <N>`

डिफ़ॉल्ट रूप से प्रति रन अधिकतम 1000 स्ट्रीम पुनर्प्राप्त होते हैं। सीमा, क्षतिग्रस्त रिकॉर्ड और टाइमआउट स्पष्ट दिखते हैं। सहेजे गए नामों में क्वारंटीन एक्सटेंशन होता है; साक्ष्य के डायरेक्टरी ढाँचे को फिर नहीं बनाया जाता।

`YaraMFTResults.csv` / `YaraMFTResults.jsonl` · `RecoveredMFT/` · `.quarantined`
