# 統合タイムライン { #super-timeline }

`super-timeline` は解析済みアーティファクトを共通スキーマのイベントに変換し、時系列に並べます。Prefetch の複数の実行時刻や、MFT の8つ以上のファイル時刻は、それぞれ意味を明記した別イベントになります。異なる証拠を比較する際も、各時刻が何を表すかを確認できます。

元の証拠ディレクトリではなく、[`auto-parse`](auto-parse.md) の解析結果を入力してください。

```bash
juntei auto-parse -d evidence/ -o parsed/
juntei super-timeline -d parsed/ -o SuperTimeline.csv
```

解析結果、マニフェスト、元の証拠は保管してください。タイムラインは分析用の表示であり、元のレコードを置き換えず、Plaso 形式のストレージも作成しません。

## 使用方法 { #usage }

```bash
# Native CSV (default)
juntei super-timeline -d parsed/ -o SuperTimeline.csv

# Native JSON Lines
juntei super-timeline -d parsed/ -o SuperTimeline.jsonl -t jsonl

# Combine native records and an existing Hayabusa JSONL timeline
juntei super-timeline -f NativeRecords.jsonl --hayabusa Hayabusa.jsonl \
  -o SuperTimeline.jsonl -t jsonl

# Timesketch import profile; also available with CSV
juntei super-timeline -d parsed/ -o Timesketch.jsonl -t jsonl --profile timesketch

# One standalone CSV needs an artifact identifier and, if unavailable, a computer name
juntei super-timeline -f MFT.csv --input-artifact mft --computer HOST01 \
  -o Host01Timeline.csv

# Reduce the time range, memory used by sorting, or number of workers
juntei super-timeline -d parsed/ -o IncidentTimeline.jsonl -t jsonl \
  --timeline-start "2026-10-20T06:00:00Z" --timeline-end "2026-10-20T14:00:00Z" \
  --memory-limit 64 -T 4 --temp-dir scratch/
```

`--hayabusa FILE` は単独でも複数回でも指定でき、Hayabusa を実行せずに既存のイベント／アラート時刻とルール情報を取り込みます。`Details` が文字列の情報レベルのイベントにも対応します。`--artifact mft,prefetch` で対象アーティファクトを限定できます。時間範囲は両端を含み、明示的な UTC オフセットまたは `Z` が必要です。

### 入力の選び方 { #choosing-an-input }

| 入力 | 識別方法 |
|---|---|
| `-d DIR` | `manifest.json` から成功した主タスク、アーティファクトID、ホスト、出力ファイルを取得します。二重取り込みを避けるため、副タスクの `auto-parse -j` は除外します。 |
| `-f FILE` | ネイティブ JSON／JSONL は埋め込まれた `Artifact` と `Comp` を使います。識別情報のない出力には `--input-artifact` が必要で、単体の CSV では常に必須です。 |
| `--computer NAME` | レコードにホスト名がない場合の補完値です。不明な場合は明示的に `Unknown` と表示します。 |
| `--hayabusa FILE` | Hayabusa の時刻、ルール情報、ホスト名、利用可能な `EvtxFile` を持つ JSONL。 |

現行マニフェストでは、解析結果ディレクトリの移動に対応し、記録された絶対出力パスを移動先で解決します。シンボリックリンクの参照先も含め、入力はそのディレクトリ内にある必要があります。旧形式の Amcache、SRUM、Jump Lists 個別ディレクトリにも対応します。カテゴリ別ディレクトリでは明示的な `OutputFiles` が必要です。

出力先からの相対パスと、複数テーブルを平坦に配置した現行の出力形式に対応します。ブラウザー、WebCache、Outlook、UAL を含め、自動解析が処理対象にするすべてのアーティファクトを認識します。

マニフェストが VHDX または E01 イメージを示す場合、参照元にはイメージ名と内部パスを記録し、イベントの詳細にもイメージ名を保持します。解析結果を読む際に一時作業領域は必要ありません。

元の証拠の参照先は、レコードまたは曖昧さのないマニフェストのコマンドから取得します。`-d` では、証拠ファイルは証拠ディレクトリからの相対参照、`Details.ParsedFile` とサマリーの `InputFiles` は解析結果ディレクトリからの相対参照です。サマリー内の出力・レポート名はタイムラインの出力ディレクトリを基準とします。SRUM CSV テーブルは、ホスト内の収集済み SRUDB.dat が一意に特定できる場合だけ対応付けます。それ以外では `SourceFile` は解析済みファイルを指し、`Details.RawSourceAvailable` は `false` になります。

単体の入力はファイル名で参照します。同名の入力が複数ある場合は `./Inputs/<ID>/<filename>` で区別します。証拠ルートが不明な絶対パスには `./Sources/<ID>/<filename>` という識別子を使います。これにより、解析者の絶対ディレクトリ名を出力せずに異なる出典を区別できます。元のパスは `ParsedFile` と `InputRecord` を使ってネイティブレコードで確認してください。Windows の実行ファイルパスなど、証拠自体に記録されたパスは変更しません。

## 共通のイベントフィールド { #common-event-fields }

| フィールド | 意味 |
|---|---|
| `Timestamp` | UTC の RFC 3339 形式です。安定した並べ替えのため小数点以下9桁で出力しますが、ゼロ埋めで精度が上がるわけではありません。 |
| `Comp` | 入力レコードに対応するホスト。 |
| `Artifact` | `mft`、`prefetch`、`srum`、`hayabusa` などの安定したアーティファクト識別子。 |
| `TimestampType` | `MFT SI Data modified` など、その時刻が表す意味。 |
| `User` | アダプターが取得できたアカウント名または SID。空の場合もあります。 |
| `Path` | 対象ファイル、レジストリキーなど、アーティファクト固有の対象。 |
| `Message` | タイムラインビューアー向けの短い説明。 |
| `SourceFile` | 証拠ディレクトリからの相対参照。ルートが不明な場合は相対的な出典識別子を使い、出典を特定できない場合は前述の解析済みファイルの参照にします。 |
| `SourceField` | 時刻を取得した実際のフィールド名または入れ子内の位置。 |
| `RecordID` | アーティファクト固有のレコード識別子。EVTX のレコード ID とは限りません。 |
| `Details` | 元の時刻、精度、時刻の基準と役割、解析済みファイル、入力レコード／位置、取得できた復元・ルール情報を含む構造化データ。 |

CSV の `Details` は引用符付きの JSON セルで、JSONL ではオブジェクトです。Timesketch プロファイルでは `Timestamp`、`TimestampType`、`Message` をそれぞれ `datetime`、`timestamp_desc`、`message` に変更し、他の出典フィールドは保持します。これらは [Timesketch の必須3フィールド](https://timesketch.org/guides/user/import-from-json-csv/)です。

`Details` に入るのは選択した情報であり、全バイナリデータや全フィールドではありません。長い文字列・配列・オブジェクトは制限され、`ProjectionOmitted` が付きます。完全なレコードは `Details.ParsedFile`、`InputRecord`、`Location` で参照してください。CSV の番号はヘッダー後の CSV レコード番号であり、引用符付きセル内の物理行番号ではありません。JSONL では行番号、JSON では最上位ドキュメント番号と入れ子内の位置を表します。

## 各時刻の意味 { #what-the-times-mean }

タイムスタンプは記録された対象についての証拠であり、それだけで実行や攻撃を証明しません。アダプターは次の意味を区別します。

| アーティファクト | タイムラインでの解釈 |
|---|---|
| MFT | SI／FN の変更・アクセス・メタデータ変更・作成を分け、名前の異なる FN 属性も区別します。ファイル名行で繰り返される SI は統合します。ADS 行の共有されたベースファイル時刻は除外します。FILE レコードのスラックから復元した名前は、復元された FN の独立したイベントとして残します。 |
| I30 | 保存された FN／インデックスのメタデータと、利用可能なスラック・復元情報。ディレクトリインデックスへの書き込み時刻ではありません。 |
| USN ジャーナル | ジャーナルの記録時刻と更新理由。1レコードで複数の変更を表すことがあり、それぞれの正確な開始時刻とは限りません。 |
| LogFile | 保存された redo／undo の時刻スナップショットとファイル名情報を分けて保持します。LSN やファイルオフセットは識別子であり、日時に変換しません。 |
| Prefetch | 記録された実行時刻を対応する Prefetch タイムライン出力と統合します。参照先ボリュームの作成時刻は別の意味として表示します。 |
| ブラウザーの SQLite データベース | 訪問、復元された最終訪問情報、ダウンロード開始／終了、Cookie の作成／アクセス／有効期限、フォームの初回／最終利用や削除記録。ダウンロード終了だけでは成功や実行を証明しません。Cookie の有効期限は設定値です。復元状態、信頼度、由来を保持します。 |
| Internet Explorer／旧 Edge の WebCache | 保存されたアクセス・作成・変更・有効期限・同期、ダウンロード開始、Cookie、コンテナーのアクセス・整理時刻。キャッシュの管理処理をユーザーのページ閲覧と断定しません。 |
| Outlook の PST、OST、MSG、OFT | メールの送信／配信、フォルダー・アイテム・添付の作成／変更、予定表・タスク・リマインダーの時刻、明示的に時刻型のプロパティ。予定時刻は会議の実施、通知の発火、プログラム実行を証明しません。配信時刻も既読の証拠ではありません。 |
| ユーザーアクセスログ（UAL） | 初回／最終アクセス、DBへの挿入／作成、最初／最後の確認、保存されたOS起動時刻。ロール、アカウント、送信元、日別カウンターは補足情報です。日別件数から午前0時のログオンを作り出しません。時刻のない識別情報や DNS 行は補助レポートに残します。 |
| Amcache | インベントリキーの最終書き込み、親ボリュームキーの情報、インストール日、PE リンク情報。登録の存在や LinkDate だけでは実行を証明しません。 |
| ShimCache | 保存されたファイル変更、キャッシュ更新、キーの最終書き込み。いずれも実行時刻とは断定できません。 |
| SRUM | プロバイダーの時刻／集計枠、接続開始、明示的な開始・終了、アプリ識別情報。バイト数、継続時間、カウンターを日時として扱いません。 |
| LNK | 対象の MAC 時刻、追跡識別子の作成、シェルアイテムの時刻。保存された対象情報であり、ショートカットを開いた時刻とは限りません。 |
| Jump Lists | エントリーの最終利用、追跡識別子の作成、埋め込まれた LNK の対象時刻。収集側のコンテナーファイル時刻は既定で除外します。 |
| Defender の隔離データ | エントリー時刻と保存されたリソースの作成・アクセス・書き込み時刻。抽出時刻は端末上の活動の証拠ではありません。 |
| BAM, UserAssist, FeatureUsage | 利用可能な活動時刻と、別の意味としてのキー最終書き込み。時刻のないカウンターからイベントは生成しません。 |
| RecentDocs、MRU、開く／保存の MRU、ShellBags、Office | 利用・信頼・シェルアイテムの時刻とキー情報。リストのキー時刻は、その全項目の個別の最終利用時刻ではありません。 |
| SAM と LSA シークレット | アカウントのログオン・パスワード・有効期限、シークレット設定、関連キーの時刻。認証イベントログの代わりにはなりません。 |
| サービス、TaskCache、レジストリの永続化、BCD | キー・設定情報と明示的に記録されたタスク時刻。サービスキーの書き込みだけではサービス実行を証明しません。 |
| ネットワークと USB | ネットワークプロファイル・リース、デバイスのインストール・接続・取り外しとキー情報。ネイティブ出力の USB ユーザーの MountPoints2 時刻には、対応するユーザーハイブの出典も保持します。 |
| システム情報、インストール済みプログラム、AppCompat、アプリ履歴 | 明示的なインストール・シャットダウン・インベントリ／活動・キー情報。ネイティブのシステム情報では、プロファイル・バージョン配列内の時刻も保持します。 |
| 監査ポリシー、セキュリティ設定、MuiCache、汎用レジストリ | 利用可能なキー最終書き込み。時刻のない値やカウンターはネイティブ入力に残します。 |
| Persistence Hunter | 根拠となるキー最終書き込みと関連変更時刻。検出結果そのものは、時刻付きのインストール記録や侵害の断定ではありません。 |
| Hayabusa | イベント／アラート時刻、ルール、レベル、チャネル、イベント ID、取得できた詳細。異なるルールや相関レコードは別に保持します。 |

同時刻でも意味や証拠の出典が違えば保持します。同一性の判定にはホスト、出典、アーティファクト、レコード、時刻の意味、復元状態を使います。統合行には `DuplicateCount` と件数を制限した代替パス・参照元フィールドを記録します。パスと時刻が似ているだけで別の証拠を統合しません。元の出典が不明な場合は入力レコードの識別情報を使い、異なる収集データの混同を防ぎます。

### 精度、ローカル時刻、仮定 { #precision-local-times-and-assumptions }

UTC と分かるフィールドや明示的なオフセット付き時刻は UTC に正規化します。100 ns の FILETIME を含め、元の値と精度を保持します。元のパーサーやビューアーで丸められた精度は復元できません。

シェルアイテム／FAT の一部は、パーサーが `Z` を付けてもローカル時刻を意味します。解析値と由来は保持しますが、不明な端末のタイムゾーンや以前の変換の正しさは復元・検証できません。精密なホスト間の相関には元の証拠と端末設定を確認してください。

アーティファクトでタイムゾーンが定義されていない時刻は、黙って UTC とみなさず診断に記録します。証拠上の根拠があれば、符号付きの固定オフセットを指定できます。

```bash
juntei super-timeline -f Amcache.jsonl --input-artifact amcache \
  --assume-offset "+09:00" -o Timeline.csv
```

日付だけの値にもこの指定が必要です。午前0時は**日単位の精度**を持つ仮定であり、観測された午前0時のイベントではありません。タイムゾーン名や夏時間規則には対応しません。欠損・ゼロ・無効・範囲外の値からエポック時刻のイベントを作りません。明示的で有効な 1970 年の日付は保持します。

次の2種類は既定で除外します。

- `--include-collection-times`: 収集・分析側のファイルシステムにある LNK／Jump List の元ファイルのメタデータです。`collection_filesystem` と表示して端末上の活動と区別します。
- `--include-interpreted-times`: 汎用レジストリの QWORD 値をリーダーが FILETIME と解釈したものです。実際にはカウンターの場合も多いため、`interpreted_value` と表示します。

## 補助レポート { #companion-reports }

`SuperTimeline.csv` を指定すると、次も出力します。

- `SuperTimeline.csv-Untimed.jsonl`: 利用可能なイベント時刻に対応付けられないネイティブレコードの位置。
- `SuperTimeline.csv-Diagnostics.jsonl`: 無効・曖昧な時刻、意図的に除外した共有メタデータ、元レコードの確認が必要な制約。
- `SuperTimeline.csv-Summary.json`: 入力ファイル、アーティファクト別件数、フィルター・候補・統合イベント数、出力件数、ワーカー、ソート予算・チャンク・パス数、処理時間。

補助レポート名には出力ファイル名全体を含めます。例えば `SuperTimeline.jsonl` のサマリーは `SuperTimeline.jsonl-Summary.json` で、時刻なし・診断レポートも独立します。同じベース名の CSV と JSONL を共存させられ、既存の結果を置き換える場合だけ `-C` が必要です。

タイムゾーンの仮定が必要な有効な日時は `UnresolvedTimeZones` に数え、`InvalidTimestamps` には含めません。どちらも診断レポートで追跡でき、推測のタイムスタンプは作りません。

有効な時刻が対象範囲外なら、時刻なしではなくフィルター済みとして数えます。候補数は重複統合前の件数です。`Complete: true` は選択した解析結果をすべて正常処理できたことを意味し、全アーティファクトの収集や全フィールドの時刻化、全攻撃の検出を意味しません。

CSV ではシステムプロファイル、USB ユーザーのマウントポイント、シェルアイテムなどの入れ子情報が平坦化される場合があります。必要なら情報の豊富なネイティブ JSON／JSONL を使ってください。CSV で省略された情報は復元できません。未対応のアーティファクトIDや壊れた入力は、部分的な成功ではなくエラーにします。

## 性能と出力の保護 { #performance-and-output-safety }

入力はストリーミングで並列処理し、ソートバッファーを専用の一時ディレクトリに退避します。上限付きのマージ処理により、決定的な時系列出力を作ります。秒とナノ秒の整数で比較し、1970 年以前にも対応します。同時刻の順序もワーカー数や予算に左右されません。

`--memory-limit` は合計の**ソートバッファー予算**であり、プロセスの RSS 上限ではありません。入力レコード、JSON オブジェクト・文字列、CSV バッファー、マージ用レコードには追加メモリが必要です。少額予算ではワーカーを減らします。`--max-record-size` の既定値は1レコード 16 MiB です。整形済み JSON 配列は全体を1文書と数えるため、必要なら上限を増やすか JSONL を使ってください。CSV の先読みも上限に影響します。

最終結果に加え、展開されたイベントとマージ処理の一時ディスク容量が必要です。1レコードから多数のイベントが生成されるため、入力より大きくなることがあります。必要に応じて時間・アーティファクトを絞り、空き容量を確保してください。

Ctrl+C では協調的に処理を停止し、ソート・出力準備の一時領域を削除して終了コード `130` を返します。Linux と macOS では SIGTERM と SIGHUP にも対応します。読み取り、正規化、マージ、レポート書き込み中に中断要求を確認し、結果の公開前に停止します。捕捉できない強制終了や停電では、一時ファイルが残る場合があります。

既存ファイルの置き換えには `-C` が必要です。入力、マニフェスト、参照する証拠とその保護ディレクトリは上書きできません。入力・ソートのエラーでは既存出力を変更しません。完成した各ファイルを出力先の隣に準備して個別に置き換え、タイムラインを最後に公開します。4ファイル全体のトランザクションでは**ありません**。最終書き込み時の障害で補助レポートの一部だけが置き換わる場合があるため、以前の完全な結果を残すには別のベース名を使ってください。

現行の Juntei 入力は `Comp`、`Filename`、`Args`、`Attr` などの略称を使います。MFT の CSV では `File`、`SN`、`ParentEntryNum`、`ParentSN`、`Type`、`USN`、`LogfileSN`、`HasADS` にも対応し、シーケンス番号による世代と DOS／ADS の違いを保持します。旧名も受け付け、`SourceField` には実際の入力の表記を残します。Hayabusa 入力の `Computer` はそのまま使います。ブートセクターとセキュリティ記述子はイベント時刻を持たないため、時刻なしレポートに残します。

## 新しい複数テーブル形式のパーサー { #newer-multi-table-parsers }

ネイティブ JSON／JSONL はテーブル名を持ちます。単体の CSV では、ブラウザー、WebCache、Outlook のアダプターが列構成からテーブルを識別するため、CSV の改名や自動解析の出典サフィックスで時刻の解釈は変わりません。UAL は明示的に対応した時刻フィールドを使い、カウンターや日付に似た無関係の文字列を日時と推測しません。

Outlook のプロパティは、宣言された型が単一時刻または複数時刻の場合だけ展開します。日付の文字列は文字列のままです。埋め込みメッセージのアイテムIDと親参照を保持し、添付の抽出時刻を保存済み時刻の代わりに使いません。時刻のないファイル、受信者、連絡先、プロパティもネイティブ出力と時刻なしレポートで追跡できます。

これらにも同じ CSV／JSONL 出力スキーマを使います。アーティファクトを追加しても CSV の列が何百も増えることはなく、固有情報は `Details` に入ります。
