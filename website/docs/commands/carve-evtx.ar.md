# استخلاص سجلات الأحداث { #carve-evtx }

استعد مقاطع (chunks) سجلات الأحداث التي تبقى بعد مسح ملف سجل أو حذفه: من صورة قرص، أو مساحة غير مخصصة، أو ملف ترحيل الصفحات (pagefile)، أو صورة ذاكرة. يحمل كل مقطع EVTX بحجم 64 KiB جداول السلاسل النصية والقوالب الخاصة به، لذا يمكن قراءة سجلاته دون بقية ملف السجل. ويكتب Juntei المقاطع المستعادة في صورة ملفات `.evtx` عادية، ملف لكل قناة، لفتحها في Hayabusa أو عارض الأحداث.

```bash
juntei carve-evtx -f host.E01 -o carved/
juntei carve-evtx -f host.vhdx --free-space-only -o carved-free/
juntei carve-evtx -f pagefile.sys --live-logs evidence/C/Windows/System32/winevt/Logs/ -o carved-pagefile/
juntei carve-evtx -f memory.raw -o carved-memory/ -t jsonl
```

دون `-o` يُعرض الملخص فقط.

## العثور على المقاطع { #finding-chunks }

- يُبحث عن توقيع المقطع عند كل إزاحة بايت، ويجب أن تكون قيم كل ترويسة معقولة (حجم الترويسة، وأرقام السجلات، والإزاحات). ويُبلَّغ عن المجاميع الاختبارية (checksums) دون أن تكون شرطًا: فالمقطع الذي كُتب فوق جزء منه لا يزال يحتوي على سجلات مقروءة.
- يُفك ضغط مقاطع ملفات السجل المضغوطة بضغط NTFS ‏(LZNT1، بوحدات من 16 عنقودًا). وفي صورة القرص يُستخدم حجم العنقود الخاص بوحدة التخزين؛ أما الملفات الأخرى فيُستخدم لها `--cluster-size <BYTES>` (الافتراضي 4096).
- تُتتبَّع السجلات وفق أحجامها حتى إزاحة آخر سجل المذكورة في الترويسة، ولا يوقف تكرارُ معرّف سجل هذا التتبعَ أبدًا. وبعد سجل تالف يستمر التتبع من السجل الصالح التالي. وتُسرد أيضًا السجلات القديمة الموجودة في المساحة الراكدة (slack) للمقطع.

## صور الأقراص ووحدات تخزين NTFS { #disk-images }

مع صورة E01 أو VHDX، أو قرص أو وحدة تخزين خام بنظام NTFS، يُصنَّف كل مقطع حسب العنقود الذي يقع فيه:

| الموقع | المعنى |
|---|---|
| `FreeSpace` | عنقود لا يستخدمه أي ملف. |
| `DeletedLog` | عنقود حر لا يزال سجل `$MFT` الخاص بملف سجل محذوف يسرده، أو ملف سجل أُعيد بناؤه من هذه العناقيد. |
| `LiveLog` | عنقود لسجل أحداث قيد الاستخدام. يُستبعد ما لم يُحدَّد `--keep-live`. |
| `AllocatedFile` | عنقود لملف آخر، مثل `pagefile.sys` أو ملف المخزن الخاص بنسخة ظل. |
| `AllocatedUnknown` | عنقود مخصص لا يسرده أي سجل `$MFT`. |
| `OutsideVolumes` | خارج كل وحدات تخزين NTFS في القرص. |
| `Unclassified` | لا يحتوي المُدخل على وحدة تخزين NTFS (ملف ترحيل الصفحات أو صورة ذاكرة). |

ملفات السجل المحذوفة التي لا يسرد سجل `$MFT` الخاص بها إلا عناقيد حرة يُعاد بناؤها كاملة، بما فيها المضغوطة، وتُحفظ تحت `Recovered/`. ويبحث `--free-space-only` في العناقيد الحرة فقط: وهو أسرع، لكنه يتخطى ملف ترحيل الصفحات ونسخ الظل والملفات الأخرى.

## إزالة التكرار { #deduplication }

يُكتب كل مقطع مرة واحدة. ويُستبعد المقطع إذا كان ينتمي إلى سجل أحداث نشط، أو كان مطابقًا لمقطع آخر، أو كانت كل سجلاته موجودة في سجلات الأحداث النشطة أو في مقطع سبقت كتابته. وتُفحص المقاطع التي تحتوي على سجلات أكثر أولًا، لذا لا تضيف النسخة الأقدم والأقصر من مقطع ما شيئًا. وإذا كان المُدخل لا يحتوي على NTFS، فحدّد سجلات الأحداث النشطة باستخدام `--live-logs <DIR>`.

## النتائج { #results }

- `Carved/<CHANNEL>.evtx`: ملف سجل واحد لكل قناة، يُسمّى كما يسمّي Windows ملفات السجل (`Microsoft-Windows-Sysmon%4Operational.evtx`). يُعاد ترقيم السجلات في ترويسات المقاطع ويُعاد حساب المجاميع الاختبارية. ويصبح السجل التالف وكل ما بعده مساحة راكدة. وفيما عدا ذلك يُحتفظ بكل مقطع كاملًا، بما في ذلك مساحته الراكدة، لذا يظل استرداد السجلات، مثل الخيار `-x` في Hayabusa، يعمل عليه.
- `Recovered/Volume<N>/...`: ملفات السجل المحذوفة التي أُعيد بناؤها من سجلات `$MFT` الخاصة بها.
- `chunks.csv` / `chunks.jsonl`: كل مقطع عُثر عليه: أين كان، وما آل إليه (`Status`)، وقناته، ومعرّفات سجلاته، وأوقاته، وحالة مجموعه الاختباري.
- `records.csv` / `records.jsonl`: كل سجل في المقاطع المكتوبة. ويميّز `OnlyInCarvedData` السجلات غير الموجودة في سجلات الأحداث النشطة.

```bash
hayabusa csv-timeline -d carved/Carved -a -o carved-timeline.csv
```

لا يعثر الاستخلاص إلا على المقاطع المتصلة. والمقطع المقسّم على عناقيد غير متجاورة، أو على صفحات فعلية غير متجاورة في الذاكرة، يكون ناقصًا، وقد تكون سجلاته اللاحقة تالفة أو مفقودة. فُك ضغط `hiberfil.sys` أولًا. ويكون رمز الخروج 0 عند اكتمال البحث و1 عند حدوث خطأ.
