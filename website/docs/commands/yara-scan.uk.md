# Сканування YARA { #yara-scan }

Перевірка зібраних файлів переносним рушієм Rust. Підтримуються Windows, macOS і Linux. Файли читаються як дані й ніколи не запускаються. Команда незалежна від автоматичного розбору артефактів.

## Вибір правил { #choose-rules }

Типовий набір Core надає перевагу точності та швидкодії. Extended розширює пошук. Full має найбільше охоплення, але може давати більше хибних спрацювань.

```bash
juntei yara-scan -d evidence/ -o yara-core/
juntei yara-scan -d evidence/ --ruleset extended -o yara-extended/
juntei yara-scan -d evidence/ --ruleset full -o yara-full/ -t jsonl
juntei yara-scan -d evidence/ --rules local-rules/ -o yara-offline/
```

`--rules <FILE_OR_DIRECTORY>`: Локальний файл або каталог правил UTF-8 без завантаження. Каталоги обходяться рекурсивно. Включення залишаються в обраному каталозі та розгортаються один раз у порядку залежностей. Недійсні або непідтримувані правила зупиняють компіляцію, а не мовчки відкидаються.

## Обмеження та охоплення { #limits-and-scope }

Перевіряються всі звичайні файли, зокрема відновлені з карантину. Символічні посилання й спеціальні файли пропускаються. Архіви та образи дисків не розпаковуються; оперативна пам’ять процесів не сканується. Використовуйте стабільні видобуті файли й новий вихідний каталог поза доказами.

- `-T, --threads <N>`: Кількість паралельних перевірок: типово число процесорів, не більше 8.
- `--timeout <SECONDS>`: Ліміт оцінювання одного файла в секундах; типово 60.
- `--max-file-mib <MIB>`: Необов’язковий максимальний розмір файла в MiB; типово без обмеження. Також діє для MFT, якщо не перевизначено. Файли понад явно задану межу позначаються пропущеними.
- `--rules-release YYYYMMDD`: Дата випуску Forge або типове latest. Завантажені джерела та хеші зберігаються для відтворення.

## Результати { #results }

- `YaraDetections.csv` / `YaraDetections.jsonl`: Збіги правил і файлів із відносними шляхами, назвами вихідних комп’ютерів, хешами, метаданими та обмеженою кількістю позицій збігів. Самі байти збігів не експортуються.
- `YaraFiles.csv` / `YaraFiles.jsonl`: Охоплення кожного файла, включно з пропусками, помилками читання, тайм-аутами та частковими результатами.
- `Summary.json`: Стан завершення, параметри, лічильники, версія рушія та хеші джерел.
- `Rules.yar`: Точні завантажені правила або знімок локальних правил із розгорнутими включеннями.
- `CompilationWarnings.txt` / `CompilationError.txt`: Попередження компілятора або помилка компіляції.

Коди виходу: 0 — завершено, 3 — неповне охоплення, 2 — помилка налаштування/запису, 130 — скасування. Збіг є зачіпкою, а не доказом компрометації; відсутність збігів не доводить безпечність. Перевіряйте назви правил і контекст артефакту. Вміст карантину слід спершу розшифрувати.

## Збіги MFT та відновлення { #mft-recovery }

MFT скануються по одній як необроблені байти без типового обмеження розміру. Записи в місцях збігів розбираються, а резидентні потоки DATA перевіряються окремо. Відновлюються лише потоки, що самостійно відповідають правилу. Збіги метаданих, між записами та нерезидентних даних повідомляються без експорту вмісту.

`--max-file-mib <MIB>` → `--max-mft-mib <MIB>` · `--max-mft-recoveries <N>`

Типово відновлюється не більше 1000 потоків за запуск. Обмеження, пошкодження та тайм-аути явно відображаються. Збережені назви отримують карантинне розширення; каталоги доказів не відтворюються.

`YaraMFTResults.csv` / `YaraMFTResults.jsonl` · `RecoveredMFT/` · `.quarantined`
