# 슈퍼 타임라인 { #super-timeline }

`super-timeline`는 구문 분석된 아티팩트를 공통 스키마를 사용하여 이벤트로 변환하고 시간별로 정렬합니다. Prefetch 레코드에는 여러 실행 시간이 포함될 수 있습니다. MFT 레코드에는 8개 이상의 파일 타임스탬프가 포함될 수 있습니다. 각각은 별도로 라벨이 지정된 이벤트가 됩니다. 이렇게 하면 각 타임스탬프가 실제로 의미하는 바를 잃지 않고 다양한 소스의 증거를 더 쉽게 비교할 수 있습니다.

원래 증거 디렉터리 대신 [`auto-parse`](auto-parse.md)의 결과로 시작합니다.

```bash
juntei auto-parse -d evidence/ -o parsed/
juntei super-timeline -d parsed/ -o SuperTimeline.csv
```

구문 분석된 파일, 매니페스트 및 원본 증거를 보관하세요. 타임라인은 분석을 위한 예측입니다. 해당 레코드를 대체하거나 기본 Plaso 스토리지 파일을 생성하지 않습니다.

## 사용법 { #usage }

```bash
# Native CSV (default)
juntei super-timeline -d parsed/ -o SuperTimeline.csv

# Native JSON Lines
juntei super-timeline -d parsed/ -o SuperTimeline.jsonl -t jsonl

# Combine native records and an existing Hayabusa JSONL timeline
juntei super-timeline -f NativeRecords.jsonl --hayabusa Hayabusa.jsonl \
  -o SuperTimeline.jsonl -t jsonl

# Timesketch import profile; also available with CSV
juntei super-timeline -d parsed/ -o Timesketch.jsonl -t jsonl --profile timesketch

# One standalone CSV needs an artifact identifier and, if unavailable, a computer name
juntei super-timeline -f MFT.csv --input-artifact mft --computer HOST01 \
  -o Host01Timeline.csv

# Reduce the time range, memory used by sorting, or number of workers
juntei super-timeline -d parsed/ -o IncidentTimeline.jsonl -t jsonl \
  --timeline-start "2026-10-20T06:00:00Z" --timeline-end "2026-10-20T14:00:00Z" \
  --memory-limit 64 -T 4 --temp-dir scratch/
```

`--hayabusa FILE`는 반복되거나 단독으로 사용될 수 있습니다. Hayabusa를 실행하지 않고 기존 이벤트/경고 타임스탬프 및 규칙 컨텍스트를 가져옵니다. `Details`가 문자열인 정보 이벤트가 지원됩니다. `--artifact mft,prefetch`는 투영을 선택한 아티팩트 식별자로 제한합니다. 시간 제한은 포함되며 명시적인 UTC 오프셋 또는 `Z`가 필요합니다.

### 입력 선택 { #choosing-an-input }

| 입력 | 식별 방법 |
|---|---|
| `-d DIR` | `manifest.json`는 성공한 기본 작업, 아티팩트 ID, 컴퓨터 및 정확한 출력 파일을 제공합니다. 두 복사본을 모두 가져오지 못하도록 보조 `auto-parse -j` 작업이 제외됩니다. |
| `-f FILE` | 기본 JSON/JSONL는 포함된 `Artifact` 및 `Comp` 필드를 사용합니다. 태그가 지정되지 않은 내보내기에는 `--input-artifact`가 필요합니다. 독립형 CSV에는 항상 이 항목이 필요합니다. |
| `--computer NAME` | 입력 레코드에 컴퓨터 이름이 없는 경우 대체. 그렇지 않으면 알 수 없는 컴퓨터는 명시적으로 `Unknown`입니다. |
| `--hayabusa FILE` | Hayabusa 타임스탬프가 포함된 JSONL, 규칙 메타데이터, 컴퓨터 및 `EvtxFile`(있는 경우). |

현재 매니페스트는 구문 분석된 디렉터리의 재배치를 지원합니다. 기록된 절대 출력 경로는 새 디렉터리에서 확인됩니다. 기호 링크 대상을 포함하여 입력은 그 안에 남아 있어야 합니다. 레거시 아티팩트별 Amcache, SRUM 및 Jump Lists 디렉터리가 지원됩니다. 카테고리 디렉토리에는 명시적인 `OutputFiles`가 필요합니다.

출력 상대 경로 및 평면화된 다중 테이블 내보내기가 포함된 현재 매니페스트가 지원됩니다. 이 명령은 최신 브라우저, WebCache, Outlook 및 UAL 테이블을 포함하여 자동 구문 분석으로 예약된 모든 아티팩트를 인식합니다.

매니페스트가 VHDX 또는 E01 이미지를 식별하면 소스 참조에는 이미지와 내부 경로가 포함되며 이미지 이름은 이벤트 컨텍스트에 유지됩니다. 구문 분석된 결과를 읽는 데 임시 스테이징 작업공간이 필요하지 않습니다.

원시 소스는 레코드 또는 명확한 매니페스트 명령에서 가져옵니다. SRUM CSV 테이블은 호스트에 고유하게 식별 가능한 수집된 SRUDB.dat가 하나 있는 경우에만 데이터베이스에 할당될 수 있습니다. 그렇지 않으면 `SourceFile`는 구문 분석된 파일을 가리키고 `Details.RawSourceAvailable`는 `false`입니다. 해당 폴백을 원시 증거 경로로 착각하지 마십시오.

## 공통 이벤트 필드 { #common-event-fields }

| 필드 | 의미 |
|---|---|
| `Timestamp` | UTC RFC 3339는 일관된 순서를 위해 9자리 소수로 작성됩니다. 패딩은 정밀도를 추가하지 않습니다. |
| `Comp` | 입력 레코드와 연결된 컴퓨터입니다. |
| `Artifact` | `mft`, `prefetch`, `srum` 또는 `hayabusa`와 같은 안정적인 아티팩트 식별자입니다. |
| `TimestampType` | `MFT SI Data modified`와 같은 타임스탬프의 의미에 대한 설명입니다. |
| `User` | 어댑터에 계정이 있는 경우 기록된 계정 또는 SID입니다. 비어 있을 수 있습니다. |
| `Path` | 영향을 받는 파일, 레지스트리 키 또는 기타 아티팩트 관련 개체입니다. |
| `Message` | 타임라인 뷰어에 대한 간단한 설명입니다. |
| `SourceFile` | 해결 가능한 경우 원시 증거 경로. 그렇지 않으면 위에서 설명한 구문 분석된 파일 대체입니다. |
| `SourceField` | 타임스탬프에 사용되는 정확한 구문 분석된 필드 또는 중첩 위치입니다. |
| `RecordID` | 아티팩트별 레코드 ID입니다. 반드시 EVTX 레코드 ID일 필요는 없습니다. |
| `Details` | 원본 타임스탬프, 정밀도, 시간 기준, 시간 역할, 구문 분석된 파일, 입력 레코드/위치 및 사용 가능한 복구/규칙 메타데이터를 포함한 구조화된 컨텍스트입니다. |

CSV에서 `Details`는 인용된 JSON 셀입니다. JSONL에서는 객체입니다. Timesketch 프로필은 다른 출처 필드를 유지하면서 `Timestamp`, `TimestampType` 및 `Message`를 각각 `datetime`, `timestamp_desc` 및 `message`로 변경합니다. 이는 [3개의 필수 타임 스케치 가져오기 필드](https://timesketch.org/guides/user/import-from-json-csv/)입니다.

`Details`에는 전체 이진 데이터나 모든 기본 레코드 필드가 아닌 선택한 컨텍스트가 의도적으로 포함되어 있습니다. 긴 문자열, 배열 및 개체는 `ProjectionOmitted`로 제한되고 표시됩니다. 전체 기본 레코드를 검사하려면 `Details.ParsedFile`, `InputRecord` 및 `Location`를 찾아보세요. CSV의 경우 레코드 번호는 인용된 셀 내부의 물리적 줄이 아니라 헤더 뒤의 CSV 레코드를 계산합니다. JSONL의 경우 행 번호입니다. JSON의 경우 최상위 문서 번호에 중첩 위치를 더한 것입니다.

## 시대의 의미 { #what-the-times-mean }

타임스탬프는 기록된 객체에 대한 증거입니다. 이는 그 자체로는 처형이나 공격의 증거가 아닙니다. 어댑터는 의도적으로 다음과 같은 구별을 유지합니다.

| 유물 | 타임라인 해석 |
|---|---|
| MFT | SI 및 FN 수정, 액세스, 메타데이터 변경 및 생성 시간을 분리합니다. FN라는 이름의 속성은 고유하게 유지됩니다. 파일 이름 행의 반복되는 SI 필드가 통합됩니다. ADS 행의 공유 기본 파일 시간은 제외됩니다. 복구된 FILE 레코드 여유 이름은 별도의 복구된 FN 이벤트를 유지합니다. |
| I30 | 사용 가능한 경우 슬랙/복구 컨텍스트와 함께 FN/인덱스 메타데이터를 저장했습니다. 이는 디렉터리 인덱스 쓰기의 타임스탬프가 아닙니다. |
| USN 저널 | 저널 기록 타임스탬프 및 업데이트 이유. 기록은 여러 가지 변경 사항을 설명할 수 있습니다. 정확한 시작 시간을 반드시 기록할 필요는 없습니다. |
| LogFile | 저장된 다시 실행/실행 취소 타임스탬프 스냅샷 및 파일 이름 메타데이터. 다시 실행과 실행 취소는 별도로 유지됩니다. LSN 및 파일 오프셋은 식별자이며 날짜로 변환되지 않습니다. |
| Prefetch | 기록된 실행 시간은 일치하는 Prefetch 타임라인 내보내기와 통합됩니다. 참조된 볼륨 생성 메타데이터에는 별도로 레이블이 지정됩니다. |
| 브라우저 SQLite 데이터베이스 | 기록된 방문, 복구된 페이지 마지막 방문 메타데이터, 다운로드 시작/종료, 쿠키 생성/액세스/만료 및 양식 기록 최초/마지막 사용 또는 삭제 묘비. 다운로드 종료 자체가 성공이나 실행을 증명하는 것은 아닙니다. 쿠키 만료는 구성된 기한입니다. 복구 상태, 신뢰도 및 출처는 맥락에 따라 유지됩니다. |
| Internet Explorer/레거시 Edge WebCache | 저장된 항목 액세스, 생성/수정, 만료 및 동기화, 다운로드 시작, 쿠키 메타데이터 및 컨테이너 액세스/청소. 캐시 기록은 사용자가 페이지를 열었다는 자동 증거가 아닙니다. |
| 아웃룩 PST, OST, MSG 및 OFT | 메시지 제출/전달 폴더, 항목 및 첨부 파일 생성/수정; 달력 시작/종료/알림; 작업 시작/기한/완료/알림; 그리고 명시적으로 입력된 시간 속성. 예정된 시간은 회의 발생, 알림 실행 또는 프로그램 실행을 증명하지 않습니다. 저장된 배달 시간은 메시지를 읽었다는 것을 증명하지 않습니다. |
| 사용자 액세스 로깅(UAL) | 첫 번째/마지막 액세스 메타데이터, 데이터베이스 삽입/생성, 첫 번째/마지막 확인 및 저장된 운영 체제 부팅 시간. 역할, 계정, 소스 주소 및 일일 카운터는 컨텍스트로 유지됩니다. 일일 날짜/개수는 자정 로그온으로 만들어지지 않습니다. 시간이 지정되지 않은 ID 및 DNS 행은 동반 보고서에서 계속 사용할 수 있습니다. |
| Amcache | 인벤토리 키 마지막 쓰기, 상위 볼륨 키 컨텍스트, 기록된 설치 날짜 및 PE 링크 메타데이터. 인벤토리 존재 또는 LinkDate만으로는 실행이 입증되지 않습니다. |
| ShimCache | 저장된 파일 수정 시각, 캐시 업데이트 메타데이터 및 캐시 키의 마지막 쓰기 시각입니다. 이 중 어느 것도 자동으로 실행 시각을 의미하지 않습니다. |
| SRUM | 제공자 타임스탬프/버킷, 연결 시작, 명시적인 시작/종료 간격 필드 및 애플리케이션 식별자 메타데이터. 바이트, 기간 및 기타 카운터는 날짜가 아닙니다. |
| LNK | MAC 타임스탬프, 추적 식별자 생성 및 셸 항목 시간을 대상으로 합니다. 바로가기가 열렸을 때 반드시 필요한 것은 아니지만 저장된 대상 메타데이터를 설명합니다. |
| Jump Lists | 항목 마지막 사용 메타데이터, 추적 식별자 생성 및 내장된 LNK 목표 시간. 기본값은 컬렉션 측 컨테이너 파일 시간을 생략합니다. |
| Defender 격리 | 항목 타임스탬프 및 저장된 리소스 생성/액세스/쓰기 시간입니다. 추출 시간은 엔드포인트 활동의 증거가 아닙니다. |
| BAM, UserAssist, FeatureUsage | 존재하는 경우 기록된 활동 필드는 주요 마지막 쓰기 컨텍스트와 함께 고유하게 유지됩니다. 시간이 없는 카운터는 이벤트를 생성하지 않습니다. |
| RecentDocs, MRU, 열기/저장 MRU, ShellBags, Office | 기록된 사용/신뢰/셸 항목 시간 및 주요 컨텍스트입니다. 목록의 주요 시간은 목록에 있는 모든 항목의 개별 마지막 사용 시간이 아닙니다. |
| SAM 및 LSA 비밀 | 기록된 계정 로그온/비밀번호/만료 또는 비밀 설정 메타데이터 및 관련 키 시간. 이는 인증 이벤트 로그를 대체하지 않습니다. |
| 서비스, TaskCache, 레지스트리 지속성, BCD | 키/구성 메타데이터 및 명시적으로 기록된 작업 시간. 서비스 키 쓰기만으로는 서비스 실행이 입증되지 않습니다. |
| 네트워크 및 USB | 네트워크 프로필/임대 및 장치 설치/도착/제거 필드(레지스트리 키 컨텍스트 포함) 기본 USB 사용자 MountPoints2 시간은 해당 사용자 하이브 소스를 유지합니다. |
| 시스템 정보, 설치된 프로그램, AppCompat, 애플리케이션 기록 | 명시적 설치, 종료, 인벤토리/활동 및 주요 메타데이터 필드. 기본 시스템 정보 프로필/버전 배열은 중첩된 시간을 유지합니다. |
| 감사 정책, 보안 설정, MuiCache, 일반 레지스트리 | 제공된 경우 주요 마지막 쓰기 시간입니다. 시간이 정해지지 않은 값/카운터는 기본 입력에서 계속 사용할 수 있습니다. |
| Persistence Hunter | 주요 마지막 쓰기 및 상관된 변경 시간을 지원합니다. 결과 자체는 타임스탬프가 표시된 설치나 손상 판정이 아닙니다. |
| Hayabusa | 규칙, 수준, 채널, 이벤트 ID 및 사용 가능한 세부 정보 컨텍스트가 포함된 이벤트/경고 타임스탬프입니다. 여러 규칙과 개별 상관 행은 별도로 유지됩니다. |

의미가 다르거나 증거 소스가 다른 여러 개의 동일한 타임스탬프가 유지됩니다. 중복 ID에는 컴퓨터, 소스, 아티팩트, 기록, 시간 의미 및 복구 상태가 포함됩니다. 통합 행은 `DuplicateCount` 및 제한된 대체 경로/소스 필드를 기록합니다. 서로 다른 소스는 경로와 타임스탬프가 비슷하다는 이유만으로 병합되지 않습니다. 원시 소스를 확인할 수 없는 경우 다른 캡처가 붕괴되는 것을 방지하기 위해 입력 레코드 ID가 유지됩니다.

### 정밀도, 현지 시간 및 가정 { #precision-local-times-and-assumptions }

알려진 UTC 필드와 명시적인 오프셋이 있는 타임스탬프는 UTC로 정규화됩니다. 100 ns FILETIME을 포함하여 원래 값과 기록된 정밀도가 유지됩니다. 소스 파서 또는 다운스트림 뷰어가 이미 시간을 반올림했을 수 있습니다. 이 명령은 손실된 정밀도를 복원할 수 없습니다.

일부 쉘 항목/FAT 필드는 업스트림 구문 분석기가 `Z`로 직렬화하는 경우에도 로컬 시간 의미를 갖습니다. 타임라인은 구문 분석된 값과 필드 출처를 유지합니다. 누락된 엔드포인트 시간대를 복구하거나 업스트림 변환을 확인할 수 없습니다. 정확한 호스트 간 상관 관계를 위해 이러한 시간을 사용하기 전에 원시 아티팩트 및 엔드포인트 설정을 확인하십시오.

UTC로 자동으로 처리되지 않고 아티팩트 정의 시간대가 없는 순진한 타임스탬프가 진단됩니다. 증거가 이를 정당화하는 경우 서명된 고정 오프셋을 제공합니다.

```bash
juntei super-timeline -f Amcache.jsonl --input-artifact amcache \
  --assume-offset "+09:00" -o Timeline.csv
```

날짜 전용 값에도 해당 옵션이 필요합니다. 자정 앵커는 **일 정밀도**를 사용하는 가정으로 표시됩니다. 그것은 관찰된 자정 사건이 아닙니다. 시간대 이름과 일광 절약 시간제 규칙은 허용되지 않습니다. 누락된 값, 0인 값, 유효하지 않은 값, 범위를 벗어난 값은 합성 에포크 이벤트를 생성하지 않습니다. 명시적으로 기록된 유효한 1970 날짜가 유지됩니다.

두 가지 선택 범주는 기본적으로 제외됩니다.

- `--include-collection-times`: LNK/Jump 목록 수집/분석 파일 시스템의 소스 파일 메타데이터입니다. 이러한 이벤트에는 엔드포인트 활동과 별도로 `collection_filesystem`라는 레이블이 지정됩니다.
- `--include-interpreted-times`: 레지스트리 판독기에 의해 FILETIME로 렌더링된 일반 레지스트리 QWORD 값입니다. 이러한 값 중 다수가 실제로 카운터이기 때문에 `interpreted_value`라는 레이블이 지정됩니다.

## 동반자 보고서 { #companion-reports }

`SuperTimeline.csv` 또는 `SuperTimeline.jsonl`의 경우 명령은 다음도 씁니다.

- `SuperTimeline-Untimed.jsonl`: 사용 가능한 매핑된 이벤트 타임스탬프가 없는 기본 레코드 위치입니다.
- `SuperTimeline-Diagnostics.jsonl`: 유효하지 않거나 모호한 시간, 의도적으로 건너뛴 공유 메타데이터 및 원본 구문 분석 레코드가 필요한 충실도 제한.
- `SuperTimeline-Summary.json`: 입력 파일, 아티팩트당 개수, 필터링된/후보/통합된 이벤트, 출력 개수, 작업자, 정렬 예산/청크/통과 및 경과 시간.

요청된 범위를 벗어난 유효한 시간이 있는 레코드는 시간이 지정되지 않은 것이 아니라 필터링된 것으로 계산됩니다. 후보 이벤트 수가 중복 연결보다 우선합니다. `Complete: true`는 선택된 모든 구문 분석된 입력이 성공적으로 처리되었음을 의미합니다. 이는 모든 아티팩트가 수집되었거나 모든 필드에 타임스탬프가 기록되었거나 모든 공격이 감지 가능하다는 의미는 아닙니다.

CSV 내보내기는 중첩된 메타데이터를 평면화할 수 있습니다. 시스템 정보 프로필, USB 사용자 마운트 지점, 셸 항목 및 기타 구조화된 컨텍스트는 기본 JSON/JSONL에서 더욱 풍부해질 수 있습니다. 해당 필드가 중요한 경우 기본 입력을 사용하세요. 타임라인은 CSV 내보내기에서 생략된 데이터를 재구성할 수 없습니다. 지원되지 않는 아티팩트 ID 및 잘못된 형식의 입력 파일은 부분적인 결과를 포함하는 성공 대신 오류를 발생시킵니다.

## 성능 및 출력 안전 { #performance-and-output-safety }

입력은 병렬로 스트리밍 및 처리됩니다. 정렬 버퍼가 개인 임시 디렉토리로 유출된 다음 제한된 병합 패스가 결정적인 연대순 출력을 생성합니다. 정렬에서는 1970 이전 날짜를 포함하여 전체 정수 초 및 나노초를 사용합니다. 동일 시간 주문은 작업자 수와 정렬 예산에 따라 결정됩니다.

`--memory-limit`는 프로세스 RSS 제한이 아닌 집계 **정렬 버퍼 예산**입니다. 입력 레코드, JSON 개체/문자열 오버헤드, CSV 버퍼 및 병합 레코드에는 추가 메모리가 필요합니다. 적은 예산으로 인해 작업자 수가 줄어듭니다. `--max-record-size`는 구문 분석된 입력 레코드를 제한합니다(기본값 16 MiB). 예쁜 JSON 배열/보고서는 하나의 최상위 입력 문서로 간주됩니다. 더 큰 문서에는 더 높은 제한이 필요할 수 있으며 JSONL가 바람직합니다. CSV 파서 미리 읽기도 이 제한에 영향을 미칩니다.

임시 디스크 공간은 최종 결과 외에도 확장된 이벤트 및 병합 패스를 수용해야 합니다. 레코드는 많은 이벤트를 생성할 수 있으므로 타임라인이 입력보다 훨씬 클 수 있습니다. 적절한 경우 시간 범위/아티팩트를 필터링하고 적절한 여유 공간이 있는 임시 볼륨을 선택합니다.

기존 출력에는 `-C`가 필요합니다. 타임라인과 동반 요소는 입력, 매니페스트, 참조된 로컬 증거 또는 보호된 증거 디렉터리를 덮어쓰면 안 됩니다. 입력 오류 또는 정렬 실패로 인해 기존 출력이 그대로 유지됩니다. 완료된 파일은 대상 옆에 배치되고 개별적으로 대체되며 타임라인은 마지막에 게시됩니다. 이는 4개 파일 전체에 대한 트랜잭션이 **아닙니다**. 최종 게시 중 I/O 오류가 발생하면 일부 동반 보고서가 대체될 수 있습니다. 이전의 완전한 내보내기 문제를 유지하는 경우 각 실행에 대해 새 출력 기본 이름을 유지하십시오.

## 최신 다중 테이블 파서 { #newer-multi-table-parsers }

기본 JSON/JSONL는 각 테이블 이름을 전달합니다. 독립 실행형 CSV의 경우 브라우저, WebCache 및 Outlook 어댑터는 열 스키마에서 해당 테이블을 식별하므로 CSV의 이름을 바꾸거나 자동 구문 분석의 소스 접미사를 사용해도 타임스탬프 해석이 변경되지 않습니다. UAL는 명시적으로 알려진 타임스탬프 필드를 유지합니다. 액세스 카운터 및 관련 없는 날짜로 보이는 텍스트는 날짜로 추측되지 않습니다.

Outlook 속성 행은 선언된 유형이 시간 또는 다중 시간 유형인 경우에만 프로젝션됩니다. 날짜를 포함하는 문자열은 문자열로 유지됩니다. 포함된 메시지는 항목 ID와 상위 참조를 유지하며 첨부 파일 추출 시간은 저장된 첨부 파일 타임스탬프를 대체하지 않습니다. 시간이 지정되지 않은 파일, 수신자, 연락처 또는 속성 행은 기본 출력 및 시간이 지정되지 않은 보고서에서 추적 가능한 상태로 유지됩니다.

동일한 CSV 및 JSONL 출력 스키마가 이러한 파서에 적용됩니다. 새 아티팩트를 추가해도 수백 개의 CSV 열이 추가되지 않습니다. 아티팩트별 컨텍스트는 `Details`에 유지됩니다.
