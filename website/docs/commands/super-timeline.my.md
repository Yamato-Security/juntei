# စူပါအချိန်လိုင်း { #super-timeline }

`super-timeline` သည် ခွဲခြမ်းစိပ်ဖြာထားသော ရှေးဟောင်းပစ္စည်းများကို ဘုံအစီအစဉ်တစ်ခုဖြင့် ဖြစ်ရပ်များအဖြစ်သို့ ပြောင်းလဲကာ ၎င်းတို့ကို အချိန်အလိုက် စီပါ။ Prefetch မှတ်တမ်းတစ်ခုတွင် ကွပ်မျက်မှုအကြိမ်များစွာ ပါဝင်နိုင်သည်။ MFT မှတ်တမ်းတစ်ခုတွင် ဖိုင်အချိန်တံဆိပ် ရှစ်ခု သို့မဟုတ် ထို့ထက်ပို၍ ပါဝင်နိုင်သည်။ တစ်ခုစီသည် သီးခြားစီအမည်တပ်ထားသော ဖြစ်ရပ်တစ်ခု ဖြစ်လာသည်။ ၎င်းသည် အချိန်တံဆိပ်တစ်ခုစီ၏ အမှန်တကယ်အဓိပ္ပာယ်ကို မဆုံးရှုံးစေဘဲ မတူညီသောအရင်းအမြစ်များမှ အထောက်အထားများကို နှိုင်းယှဉ်ရန် ပိုမိုလွယ်ကူစေသည်။

မူရင်းအထောက်အထားလမ်းညွှန်ထက် [`auto-parse`](auto-parse.md) ၏ရလဒ်များဖြင့် စတင်ပါ။

```bash
juntei auto-parse -d evidence/ -o parsed/
juntei super-timeline -d parsed/ -o SuperTimeline.csv
```

ခွဲခြမ်းစိတ်ဖြာထားသော ဖိုင်များ၊ ဖော်ပြချက်များနှင့် မူရင်းအထောက်အထားများကို သိမ်းဆည်းထားပါ။ အချိန်ဇယားသည် ခွဲခြမ်းစိတ်ဖြာမှုအတွက် ခန့်မှန်းချက်တစ်ခုဖြစ်သည်။ ၎င်းသည် ထိုမှတ်တမ်းများကို အစားထိုးခြင်း သို့မဟုတ် မူရင်း Plaso သိုလှောင်မှုဖိုင်ကို ဖန်တီးခြင်းမဟုတ်ပါ။

## အသုံးပြုမှု { #usage }

```bash
# Native CSV (default)
juntei super-timeline -d parsed/ -o SuperTimeline.csv

# Native JSON Lines
juntei super-timeline -d parsed/ -o SuperTimeline.jsonl -t jsonl

# Combine native records and an existing Hayabusa JSONL timeline
juntei super-timeline -f NativeRecords.jsonl --hayabusa Hayabusa.jsonl \
  -o SuperTimeline.jsonl -t jsonl

# Timesketch import profile; also available with CSV
juntei super-timeline -d parsed/ -o Timesketch.jsonl -t jsonl --profile timesketch

# One standalone CSV needs an artifact identifier and, if unavailable, a computer name
juntei super-timeline -f MFT.csv --input-artifact mft --computer HOST01 \
  -o Host01Timeline.csv

# Reduce the time range, memory used by sorting, or number of workers
juntei super-timeline -d parsed/ -o IncidentTimeline.jsonl -t jsonl \
  --timeline-start "2026-10-20T06:00:00Z" --timeline-end "2026-10-20T14:00:00Z" \
  --memory-limit 64 -T 4 --temp-dir scratch/
```

`--hayabusa FILE` ကို ထပ်ခါထပ်ခါ သို့မဟုတ် သူ့ဘာသာသူ အသုံးပြုနိုင်သည်။ ၎င်းသည် Hayabusa ကိုအသုံးမပြုဘဲ လက်ရှိဖြစ်ရပ်/သတိပေးချက်အချိန်တံဆိပ်နှင့် စည်းကမ်းအကြောင်းအရာများကို တင်သွင်းသည်။ `Details` သည် စာကြောင်းတစ်ကြောင်းကို ပံ့ပိုးပေးထားသည့် အချက်အလက်ဆိုင်ရာ ဖြစ်ရပ်များ။ `--artifact mft,prefetch` သည် ရွေးချယ်ထားသော ရှေးဟောင်းပစ္စည်း identifiers များဆီသို့ projection ကို ကန့်သတ်ထားသည်။ အချိန်ကန့်သတ်ချက်များသည် ပါဝင်ပြီး တိကျသော UTC အော့ဖ်ဆက် သို့မဟုတ် `Z` လိုအပ်သည်။

### ထည့်သွင်းမှုတစ်ခုကို ရွေးချယ်ခြင်း။ { #choosing-an-input }

| ထည့်သွင်းခြင်း။ | ဘယ်လိုဖော်ထုတ်လဲ။ |
|---|---|
| `-d DIR` | `manifest.json` ထောက်ပံ့မှုများသည် အဓိကလုပ်ဆောင်စရာများ၊ အတုအယောင် ID များ၊ ကွန်ပျူတာများနှင့် တိကျသော အထွက်ဖိုင်များကို အောင်မြင်ခဲ့သည်။ မိတ္တူနှစ်ခုစလုံးကို တင်သွင်းခြင်းကို တားဆီးရန် ဒုတိယမြောက် `auto-parse -j` လုပ်ဆောင်စရာများကို ဖယ်ထုတ်ထားသည်။ |
| `-f FILE` | မူရင်း JSON/JSONL သည် ထည့်သွင်းထားသော `Artifact` နှင့် `Comp` အကွက်များကို အသုံးပြုသည်။ တဂ်မထားသော ပို့ကုန်များသည် `--input-artifact` လိုအပ်ပါသည်။ သီးခြား CSV အမြဲလိုအပ်သည်။ |
| `--computer NAME` | ထည့်သွင်းမှု မှတ်တမ်းတွင် ကွန်ပျူတာအမည် မရှိသည့်အခါ အစားထိုးခြင်း၊ သို့မဟုတ်ပါက အမည်မသိကွန်ပျူတာသည် `Unknown` ဖြစ်သည်။ |
| `--hayabusa FILE` | JSONL နှင့်အတူ Hayabusa အချိန်တံဆိပ်တုံးများ၊ စည်းမျဉ်းမက်တာဒေတာ၊ ကွန်ပျူတာနှင့် လက်ရှိအချိန်တွင် `EvtxFile`။ |

လက်ရှိ manifests များသည် ခွဲခြမ်းစိတ်ဖြာထားသော directory ၏ နေရာရွှေ့ပြောင်းခြင်းကို ပံ့ပိုးသည်- မှတ်တမ်းတင်ထားသော absolute output လမ်းကြောင်းများကို directory အသစ်အောက်တွင် ဖြေရှင်းထားပါသည်။ သင်္ကေတ-လင့်ခ်ပစ်မှတ်များအပါအဝင် ထည့်သွင်းမှုများသည် ၎င်းအတွင်း၌ ရှိနေရပါမည်။ အမွေအနှစ်တစ်ခုချင်းစီအလိုက် Amcache၊ SRUM နှင့် Jump Lists လမ်းညွှန်များကို ပံ့ပိုးထားပါသည်။ အမျိုးအစားလမ်းညွှန်များသည် ပြတ်သားစွာ `OutputFiles` လိုအပ်သည်။

output-relative paths နှင့် flattened multi-table exports များပါရှိသော လက်ရှိ manifest များကို ပံ့ပိုးထားပါသည်။ အသစ်သောဘရောက်ဆာ၊ WebCache၊ Outlook နှင့် UAL ဇယားများအပါအဝင် အလိုအလျောက်ခွဲခြမ်းစိတ်ဖြာခြင်းဖြင့် စီစဉ်ထားသည့်အရာတိုင်းကို အမိန့်ပေးသည်။

မန်နီးဖက်စ်တစ်ခုက VHDX သို့မဟုတ် E01 ပုံတစ်ပုံကို ခွဲခြားသတ်မှတ်သောအခါ၊ ရင်းမြစ်ကိုးကားချက်များသည် ရုပ်ပုံနှင့် အတွင်းပိုင်းလမ်းကြောင်း ပါ၀င်ပြီး ရုပ်ပုံအမည်ကို ပွဲအကြောင်းအရာတွင် ထိန်းသိမ်းထားသည်။ ခွဲခြမ်းစိတ်ဖြာထားသော ရလဒ်များကို ဖတ်ရန် ယာယီအဆင့်လုပ်ဆောင်သည့်နေရာ မလိုအပ်ပါ။

ကုန်ကြမ်းရင်းမြစ်ကို မှတ်တမ်း သို့မဟုတ် မရှင်းလင်းသော မန်နီးဖက်စ် ကွန်မန်းမှ ရယူသည်။ `-d` ဖြင့်၊ ကုန်ကြမ်း-ရင်းမြစ်ကိုးကားချက်များသည် အထောက်အထားလမ်းညွှန်များနှင့် ဆက်စပ်နေပြီး `Details.ParsedFile` နှင့် အကျဉ်းချုပ် `InputFiles` တို့သည် ခွဲခြမ်းစိတ်ဖြာထားသော လမ်းညွှန်နှင့် ဆက်စပ်နေသည်။ အကျဉ်းချုပ် ရလဒ်/အစီရင်ခံစာအမည်များသည် အချိန်လိုင်း၏ ရလဒ်လမ်းညွှန်နှင့် ဆက်စပ်နေသည်။ SRUM CSV ဇယားများကို လက်ခံဆောင်ရွက်ပေးသူတွင် ထူးခြားစွာခွဲခြားသတ်မှတ်နိုင်သော SRUDB.dat တစ်ခုရှိမှသာ ဒေတာဘေ့စ်တစ်ခုသို့ တာဝန်ပေးအပ်သည်။ မဟုတ်ပါက `SourceFile` သည် ခွဲခြမ်းစိတ်ဖြာထားသောဖိုင်ကို ညွှန်ပြပြီး `Details.RawSourceAvailable` သည် `false` ဖြစ်သည်။

သီးခြားထည့်သွင်းမှုကို ၎င်း၏ဖိုင်အမည်ဖြင့် ကိုးကားထားသည်။ တူညီသော ဖိုင်အမည်ဖြင့် ထည့်သွင်းမှုများသည် ကွဲပြားသော `./Inputs/<ID>/<filename>` ရည်ညွှန်းချက်များကို အသုံးပြုသည်။ အကြွင်းမဲ့ ကုန်ကြမ်းရင်းမြစ်လမ်းကြောင်းများသည် လူသိများသော အထောက်အထားအမြစ်များအပြင် `./Sources/<ID>/<filename>` ခွဲခြားသတ်မှတ်မှုများကို အသုံးပြုသည်။ ဤအလင်းပြသော ကိုးကားချက်များသည် လေ့လာသူ၏ ပကတိလမ်းညွှန်အမည်များကို မတင်ပို့ဘဲ ရင်းမြစ်ကွဲပြားမှုများကို ထိန်းသိမ်းထားသည်။ မူရင်းအရင်းအမြစ်အတွက် `ParsedFile` နှင့် `InputRecord` ကိုအသုံးပြု၍ မူရင်းမှတ်တမ်းကို တိုင်ပင်ပါ။ Windows စီမံလုပ်ဆောင်နိုင်သော လမ်းကြောင်းများကဲ့သို့သော အထောက်အထားများတွင် မှတ်တမ်းတင်ထားသော လမ်းကြောင်းများသည် မပြောင်းလဲပါ။

## အဖြစ်များသော ကိစ္စရပ်များ { #common-event-fields }

| လယ်ကွင်း | အဓိပ္ပါယ် |
|---|---|
| `Timestamp` | UTC RFC 3339၊ တစ်သမတ်တည်း အော်ဒါမှာရန်အတွက် အပိုင်းကိန်းဂဏန်းကိုးလုံးဖြင့် ရေးသားထားသည်။ Padding သည် တိကျမှုမထည့်ပါ။ |
| `Comp` | ကွန်ပြူတာနှင့် ဆက်စပ်ရိုက်သွင်းမှုမှတ်တမ်း။ |
| `Artifact` | `mft`၊ `prefetch`၊ `srum` သို့မဟုတ် `hayabusa` ကဲ့သို့သော တည်ငြိမ်သော ရှေးဟောင်းပစ္စည်း identifier |
| `TimestampType` | `MFT SI Data modified` ကဲ့သို့သော အချိန်တံဆိပ်ခေါင်း၏ အဓိပ္ပါယ်ဖော်ပြချက်။ |
| `User` | အဒက်တာတွင် တစ်ခုရှိသောအခါ မှတ်တမ်းတင်ထားသော အကောင့် သို့မဟုတ် SID၊ ဗလာဖြစ်နိုင်သည်။ |
| `Path` | ထိခိုက်ထားသော ဖိုင်၊ မှတ်ပုံတင်ကီး သို့မဟုတ် အခြား ရှေးဟောင်းပစ္စည်းဆိုင်ရာ သီးခြားအရာဝတ္ထု။ |
| `Message` | အချိန်လိုင်းကြည့်ရှုသူအတွက် အတိုချုံးဖော်ပြချက်။ |
| `SourceFile` | အထောက်အထား-နှိုင်းရအကြမ်း-အရင်းအမြစ် ရည်ညွှန်းချက် သို့မဟုတ် ၎င်း၏အမြစ်ကို မသိသောအခါ၊ သို့မဟုတ်ပါက အထက်တွင်ဖော်ပြထားသော ခွဲခြမ်းစိတ်ဖြာသည့်ဖိုင် ဖြည့်စွက်မှု။ |
| `SourceField` | ခွဲခြမ်းစိတ်ဖြာထားသည့် အကွက်အတိအကျ သို့မဟုတ် အချိန်တံဆိပ်အတွက် အသုံးပြုသည့် အစုအဝေးတည်နေရာ။ |
| `RecordID` | Artifact-specific record အထောက်အထား။ ၎င်းသည် EVTX Record ID မလိုအပ်ပါ။ |
| `Details` | မူရင်းအချိန်တံဆိပ်ခေါင်း၊ တိကျမှု၊ အချိန်အခြေခံ၊ အချိန်အခန်းကဏ္ဍ၊ ခွဲခြမ်းစိတ်ဖြာထားသည့်ဖိုင်၊ ထည့်သွင်းမှုမှတ်တမ်း/တည်နေရာနှင့် ရရှိနိုင်သော ပြန်လည်ရယူခြင်း/စည်းမျဉ်း မက်တာဒေတာတို့ အပါအဝင် ဖွဲ့စည်းတည်ဆောက်ထားသည့် အကြောင်းအရာ။ |

CSV တွင် `Details` သည် JSON ဆဲလ်တစ်ခုဖြစ်သည်။ JSONL တွင် ၎င်းသည် အရာဝတ္ထုတစ်ခုဖြစ်သည်။ Timesketch ပရိုဖိုင်သည် `Timestamp`၊ `TimestampType` နှင့် `Message` သို့ `datetime`၊ `timestamp_desc` နှင့် `message` အသီးသီး၊ အခြားသက်သေနယ်ပယ်များကို ထိန်းသိမ်းထားစဉ်တွင် ပြောင်းလဲပါသည်။ ၎င်းတို့သည် [three လိုအပ်သော Timesketch တင်သွင်းမှုအကွက်များ](https://timesketch.org/guides/user/import-from-json-csv/) ဖြစ်သည်။

`Details` တွင် ဒွိဒေတာအပြည့်အစုံ သို့မဟုတ် မူရင်းမှတ်တမ်းအကွက်တိုင်းထက် ရွေးချယ်ထားသော အကြောင်းအရာကို တမင်တကာ ပါရှိသည်။ ကြိုးရှည်များ၊ အခင်းအကျင်းများနှင့် အရာဝတ္ထုများကို ဘောင်ခတ်ထားပြီး `ProjectionOmitted` ဟု အမှတ်အသားပြုထားသည်။ မူရင်းမှတ်တမ်းအပြည့်အစုံကို စစ်ဆေးရန် `Details.ParsedFile`၊ `InputRecord` နှင့် `Location` ကိုကြည့်ပါ။ CSV အတွက်၊ မှတ်တမ်းနံပါတ်သည် ခေါင်းစီးပြီးနောက် CSV မှတ်တမ်းများကို ကိုးကားထားသောဆဲလ်များအတွင်းရှိ ရုပ်ပိုင်းဆိုင်ရာလိုင်းများမဟုတ်ဘဲ မှတ်တမ်းများဖြစ်သည်။ JSONL အတွက် ၎င်းသည် လိုင်းနံပါတ်ဖြစ်သည်။ JSON အတွက် ၎င်းသည် ထိပ်တန်းအဆင့် စာရွက်စာတမ်းနံပါတ် နှင့် အသိုက်လုပ်ထားသော တည်နေရာဖြစ်သည်။

## အချိန်တွေက ဘာကို ဆိုလိုတာလဲ။ { #what-the-times-mean }

အချိန်တံဆိပ်ဆိုသည်မှာ မှတ်တမ်းတင်ထားသော အရာဝတ္ထုတစ်ခု၏ အထောက်အထားဖြစ်သည်။ ၎င်းသည် ကွပ်မျက်ခြင်း သို့မဟုတ် တိုက်ခိုက်မှုတစ်ခု၏ သက်သေမဟုတ်ပေ။ အဒက်တာများသည် ဤထူးခြားချက်များကို ရည်ရွယ်ချက်ရှိရှိ သိမ်းဆည်းထားသည်-

### တိကျမှု၊ ဒေသအချိန်နှင့် ယူဆချက် { #precision-local-times-and-assumptions }

ထင်ရှားသော အော့ဖ်ဆက်များပါရှိသော လူသိများသော UTC အကွက်များနှင့် အချိန်တံဆိပ်များကို UTC သို့ ပုံမှန်အဖြစ် ပြောင်းလဲထားသည်။ 100 ns FILETIMEs အပါအဝင် မူရင်းတန်ဖိုးများနှင့် ၎င်းတို့၏ မှတ်တမ်းတင်ထားသော တိကျမှုကို ထိန်းသိမ်းထားသည်။ ရင်းမြစ်ခွဲခြမ်းစိတ်ဖြာမှု သို့မဟုတ် ဒေါင်းလုဒ်ကြည့်ရှုသူသည် အချိန်တစ်ခုကို လှည့်ပြီးဖြစ်သည်။ ဤအမိန့်သည် ဆုံးရှုံးသွားသော တိကျမှုကို ပြန်မရနိုင်ပါ။

အချို့သော shell-item/FAT အကွက်များသည် အထက်စီးကြောင်းခွဲခြမ်းစိတ်ဖြာမှုတစ်ခုက ၎င်းတို့ကို `Z` ဖြင့် နံပါတ်စဉ်ပြုထားသည့်အခါတွင်ပင် ဒေသတွင်းအချိန်ဆိုင်ရာ ဝေါဟာရများရှိသည်။ အချိန်ဇယားသည် ခွဲခြမ်းစိတ်ဖြာထားသော တန်ဖိုးနှင့် အကွက်ဇာစ်မြစ်ကို ထိန်းသိမ်းသည်။ ၎င်းသည် ပျောက်ဆုံးနေသော အဆုံးမှတ်အချိန်ဇုန်ကို ပြန်လည်ရယူ၍ မရပါ သို့မဟုတ် ရေစီးကြောင်းဆိုင်ရာ ပြောင်းလဲခြင်းကို တရားဝင်အောင် မလုပ်ဆောင်နိုင်ပါ။ တိကျသောအိမ်ရှင်အပြန်အလှန်ဆက်စပ်မှုအတွက် ထိုကဲ့သို့သောအချိန်ကိုအသုံးမပြုမီ အကြမ်းထည်နှင့် အဆုံးမှတ်ဆက်တင်များကို စစ်ဆေးပါ။

UTC အဖြစ် တိတ်တဆိတ် ဆက်ဆံခြင်းထက် အတုအယောင်သတ်မှတ်ထားသော အချိန်ဇုန်မရှိသော နုံအသောအချိန်တံဆိပ်ကို ရောဂါရှာဖွေသည်။ အထောက်အထားများ ခိုင်လုံပါက၊ လက်မှတ်ရေးထိုးထားသည့် ပုံသေ အော့ဖ်ဆက်ကို ပေးဆောင်ပါ။

```bash
juntei super-timeline -f Amcache.jsonl --input-artifact amcache \
  --assume-offset "+09:00" -o Timeline.csv
```

ရက်စွဲသီးသန့်တန်ဖိုးများသည် ထိုရွေးချယ်ခွင့်လည်း လိုအပ်ပါသည်။ ၎င်းတို့၏ သန်းခေါင်ယံကျောက်ဆူးကို **နေ့တိကျမှု** ဖြင့် ယူဆချက်အဖြစ် တံဆိပ်တပ်ထားသည်။ သန်းခေါင်ယံ အဖြစ်အပျက် မဟုတ်ပါ။ အချိန်ဇုန်အမည်များနှင့် နေ့အလင်းရောင်ချွေတာရေး စည်းမျဉ်းများကို လက်မခံပါ။ ပျောက်ဆုံးနေသော၊ သုည၊ အကျုံးမဝင်သော နှင့် ဘောင်ပြင်ပ တန်ဖိုးများသည် ပေါင်းစပ်ဖြစ်ရပ်များကို မဖြစ်ပေါ်စေပါ။ အတိအလင်း မှတ်တမ်းတင်ထားသော တရားဝင် 1970 ရက်စွဲကို ထိန်းသိမ်းထားသည်။

ရွေးချယ်နိုင်သော အမျိုးအစားနှစ်ခုကို မူရင်းအတိုင်း ဖယ်ထုတ်ထားသည်-

- `--include-collection-times`- LNK/Jump List အရင်းအမြစ်-ဖိုင် မက်တာဒေတာ စုစည်းမှု/ခွဲခြမ်းစိတ်ဖြာမှု ဖိုင်စနစ်။ ဤဖြစ်ရပ်များကို အဆုံးမှတ်လုပ်ဆောင်ချက်မှ သီးခြားစီ `collection_filesystem` ဟု တံဆိပ်တပ်ထားသည်။
- `--include-interpreted-times`- မှတ်ပုံတင်စာဖတ်သူမှ QWORD တန်ဖိုးများကို FILETIME အဖြစ်ပြန်ဆိုထားသည်။ ထိုတန်ဖိုးများစွာသည် အမှန်တကယ်ကောင်တာဖြစ်သောကြောင့် ၎င်းတို့ကို `interpreted_value` ဟု တံဆိပ်တပ်ထားသည်။

## ဖော် ပြထားပါတယ်။ { #companion-reports }

`SuperTimeline.csv` အတွက်၊ command လည်းရေးသားသည်-

- `SuperTimeline.csv-Untimed.jsonl`- အသုံးပြုနိုင်သော မြေပုံပြုလုပ်ထားသော ဖြစ်ရပ်အချိန်တံဆိပ်မပါဘဲ မူရင်းမှတ်တမ်းတည်နေရာများ။
- `SuperTimeline.csv-Diagnostics.jsonl`- မူရင်းခွဲခြမ်းစိတ်ဖြာမှုမှတ်တမ်းကို လိုအပ်သည့် မမှန်ကန်သော/မရှင်းလင်းသောအချိန်များ၊ မျှဝေထားသော မက်တာဒေတာနှင့် သစ္စာရှိမှုကန့်သတ်ချက်များကို ရည်ရွယ်ချက်ရှိရှိ ကျော်သွားပါသည်။
- `SuperTimeline.csv-Summary.json`- ထည့်သွင်းဖိုင်များ၊ တစ်ပုံတစ်ပုံ အရေအတွက်များ၊ စစ်ထုတ်ထားသော/ ကိုယ်စားလှယ်လောင်း/ ပေါင်းစည်းထားသော ဖြစ်ရပ်များ၊ ထုတ်ပေးမှုအရေအတွက်၊ အလုပ်သမားများ၊ ဘတ်ဂျက်ခွဲဝေမှု/အပိုင်းများ/ဖြတ်သန်းမှုများနှင့် လွန်သွားသောအချိန်။

အဖော်အမည်များတွင် ပြီးပြည့်စုံသော အထွက်ဖိုင်အမည် ပါဝင်သည်။ ဥပမာအားဖြင့်၊ `SuperTimeline.jsonl` တွင် ၎င်း၏ကိုယ်ပိုင် `SuperTimeline.jsonl-Summary.json` နှင့် သက်ဆိုင်ရာ အချိန်မရသေးသော/ရောဂါရှာဖွေရေး အစီရင်ခံစာများ ရှိသည်။ CSV နှင့် JSONL ပို့ကုန်များသည် တူညီသောပင်စည်ဖြင့် အတူယှဉ်တွဲတည်ရှိနိုင်သည်; ရှိပြီးသားရလဒ်အစုံကိုအစားထိုးရန် `-C` လိုအပ်ပါသည်။

`InvalidTimestamps` အစား `UnresolvedTimeZones` မျှတသော အချိန်ဇုန်ယူဆချက်တိုးနှုန်းကို စောင့်မျှော်နေသည့် တရားဝင်ရက်စွဲများ။ နှစ်ခုစလုံးသည် ရောဂါရှာဖွေရေးတွင် ခြေရာခံနိုင်သေးသည်။ အချိန်တံဆိပ်ကို တီထွင်ထားခြင်းမရှိပါ။

တောင်းဆိုထားသော အပိုင်းအခြားပြင်ပတွင် တရားဝင်အချိန်များပါရှိသော မှတ်တမ်းများကို အချိန်မဆွဲဘဲ စစ်ထုတ်ထားသည့်အဖြစ် ရေတွက်ပါသည်။ ကိုယ်စားလှယ်လောင်းပွဲသည် ပွားများစုစည်းမှုကို ရှေ့တွင်ရေတွက်သည်။ `Complete: true` ဆိုသည်မှာ ရွေးချယ်ထားသော ခွဲခြမ်းစိတ်ဖြာထားသည့် ထည့်သွင်းမှုများအားလုံးကို အောင်မြင်စွာ လုပ်ဆောင်ပြီးဖြစ်သည်၊ ရှေးဟောင်းပစ္စည်းတိုင်းကို စုဆောင်းထားသည်ဟု မဆိုလိုပါ၊ နယ်ပယ်တိုင်းတွင် အချိန်တံဆိပ်ခတ်ထားခြင်း သို့မဟုတ် တိုက်ခိုက်မှုတိုင်းကို တွေ့ရှိနိုင်သည်ဟု မဆိုလိုပါ။

CSV ထုတ်ယူမှုများသည် nested metadata ကို ပြားချပ်ချပ်ဖြစ်စေနိုင်သည်- စနစ်အချက်အလက် ပရိုဖိုင်များ၊ USB အသုံးပြုသူ mount အမှတ်များ၊ shell ပစ္စည်းများနှင့် အခြားဖွဲ့စည်းပုံဆိုင်ရာ အကြောင်းအရာများသည် မူရင်း JSON/JSONL တွင် ပိုမိုကြွယ်ဝနိုင်သည်။ ထိုအကွက်များသည် အရေးကြီးသောအခါတွင် မူရင်းထည့်သွင်းမှုကို အသုံးပြုပါ။ CSV ထုတ်ယူမှုဖြင့် ချန်လှပ်ထားသော ဒေတာကို အချိန်ဇယားကို ပြန်လည်တည်ဆောက်၍မရပါ။ ပံ့ပိုးမထားသော ရှေးဟောင်း ID များနှင့် ပုံစံမမှန်သော ထည့်သွင်းမှုဖိုင်များသည် တစ်စိတ်တစ်ပိုင်းရလဒ်များပါဝင်သော အောင်မြင်မှုအစား အမှားအယွင်းဖြစ်စေသည်။

## စွမ်းဆောင်ရည်နှင့် ထွက်ရှိမှုဘေးကင်းရေး { #performance-and-output-safety }

ထည့်သွင်းမှုများကို တိုက်ရိုက်ထုတ်လွှင့်ပြီး အပြိုင်လုပ်ဆောင်သည်။ သီးသန့်ယာယီလမ်းညွှန်တစ်ခုသို့ ဖိတ်စင်နေသော ကြားခံများကို စီရန်၊ ထို့နောက် ကန့်သတ်ထားသော ပေါင်းစပ်ဖြတ်သန်းမှုများသည် အဆုံးအဖြတ်ရှိသော အချိန်နှင့်တပြေးညီ အထွက်ကို ထုတ်ပေးပါသည်။ စီရန်သည် 1970 မတိုင်မီ ရက်စွဲများအပါအဝင် ကိန်းပြည့်စက္ကန့်နှင့် နာနိုစက္ကန့်များကို အသုံးပြုသည်။ အချိန်တန်းတူ အမိန့်ပေးခြင်းသည် အလုပ်သမားအရေအတွက်နှင့် ဘတ်ဂျက်များကို အမျိုးအစားခွဲခြင်းများတွင် အဆုံးအဖြတ်ပေးသည်။

`--memory-limit` သည် စုစုပေါင်း **စီရန်-ကြားခံဘတ်ဂျက်** ဖြစ်ပြီး၊ လုပ်ငန်းစဉ် RSS ကန့်သတ်ချက်မဟုတ်ပါ။ ထည့်သွင်းမှုမှတ်တမ်းများ၊ JSON အရာဝတ္ထု/စာကြောင်းအပေါ်ရှိ၊ CSV ကြားခံများနှင့် ပေါင်းစည်းထားသည့် မှတ်တမ်းများသည် အပိုမှတ်ဉာဏ်လိုအပ်သည်။ ဘတ်ဂျက်အနည်းငယ်အတွက် အလုပ်သမားအရေအတွက်ကို လျှော့ချသည်။ `--max-record-size` သည် ခွဲခြမ်းစိတ်ဖြာထားသော ထည့်သွင်းမှုမှတ်တမ်း (မူလ 16 MiB); လှပသော JSON အခင်းအကျင်း/အစီရင်ခံစာကို ထိပ်တန်းအဆင့် ထည့်သွင်းမှုမှတ်တမ်းတစ်ခုအဖြစ် ရေတွက်သည်။ ပိုကြီးသောစာရွက်စာတမ်းများသည် ပိုမိုမြင့်မားသောကန့်သတ်ချက်လိုအပ်နိုင်သည်၊ သို့မဟုတ် ဖြစ်နိုင်လျှင် JSONL လိုအပ်နိုင်သည်။ CSV ခွဲခြမ်းစိတ်ဖြာဖတ်ခြင်း-ရှေ့ဆက်ခြင်းသည်လည်း ဤကန့်သတ်ချက်ကို ပံ့ပိုးပေးပါသည်။

ယာယီဒစ်နေရာလွတ်သည် နောက်ဆုံးရလဒ်များအပြင် တိုးချဲ့ထားသော အစီအစဉ်များနှင့် ပေါင်းစည်းခြင်းများကို လိုက်လျောညီထွေဖြစ်စေရပါမည်။ မှတ်တမ်းတစ်ခုသည် ဖြစ်ရပ်များစွာကို ထုတ်ပေးနိုင်သည်၊ ထို့ကြောင့် အချိန်ဇယားသည် ထည့်သွင်းမှုထက် များစွာပိုကြီးနိုင်သည်။ သင့်လျော်သည့်အခါ အချိန်အပိုင်းအခြား/ပစ္စည်းများကို စစ်ထုတ်ပြီး လုံလောက်သောနေရာလွတ်ဖြင့် ယာယီအသံအတိုးအကျယ်ကို ရွေးချယ်ပါ။

Ctrl+C သည် ပူးပေါင်းဆောင်ရွက်မှုဖြင့် ပယ်ဖျက်သည်၊ သီးသန့်အမျိုးအစားခွဲခြင်း/ဇာတ်ညွှန်းလမ်းညွှန်များကို ဖယ်ရှားပြီး ကုဒ် `130` ဖြင့် ထွက်သည်။ Linux နှင့် macOS တွင် ၎င်းသည် SIGTERM နှင့် SIGHUP တို့နှင့်လည်း သက်ဆိုင်ပါသည်။ ထုတ်ဝေမှုမစတင်မီ အစီရင်ခံစာများကိုဖတ်ရှုခြင်း၊ ပုံမှန်ဖြစ်အောင်ပြုလုပ်ခြင်း၊ ပေါင်းစည်းခြင်းနှင့် ရေးသားခြင်းများကို ပယ်ဖျက်ခြင်းကို စစ်ဆေးပါသည်။ ဖမ်း၍မရသော ရပ်စဲခြင်း သို့မဟုတ် ပါဝါဆုံးရှုံးခြင်းသည် ယာယီဖိုင်များကို ချန်ထားနိုင်သေးသည်။

လက်ရှိထွက်ပေါက်များသည် `-C` လိုအပ်သည်။ အချိန်ဇယားနှင့် အဖော်များသည် သွင်းအားစုများ၊ ဖော်ပြချက်များ၊ ကိုးကားထားသော ဒေသဆိုင်ရာ အထောက်အထားများ သို့မဟုတ် ၎င်းတို့၏ အကာအကွယ်ပေးထားသည့် အထောက်အထားလမ်းညွှန်များကို overwrite မလုပ်ရပါ။ ထည့်သွင်းမှု အမှားအယွင်းများ သို့မဟုတ် အမျိုးအစားခွဲရန် ပျက်ကွက်မှုများသည် ရှိပြီးသား အထွက်များကို မထိမခိုက်စေပါ။ ပြီးမြောက်သောဖိုင်များကို ဦးတည်ရာဘေးတွင် အဆင့်သတ်မှတ်ပြီး တစ်ဦးချင်း အစားထိုးကာ နောက်ဆုံးအချိန်စာရင်းကို ထုတ်ပြန်သည်။ ၎င်းသည် **မဟုတ်ပါ** ဖိုင်လေးခုလုံးတွင် ငွေပေးငွေယူတစ်ခုဖြစ်သည်- နောက်ဆုံးထုတ်ဝေမှုအတွင်း I/O ချို့ယွင်းမှုတစ်ခုသည် အဖော်အစီရင်ခံစာအချို့ကို အစားထိုးထားနိုင်သည်။ အစောပိုင်းပြီးပြည့်စုံသော ပို့ကုန်ကိစ္စများကို ဆက်လက်ထိန်းသိမ်းထားသည့်အခါ လုပ်ဆောင်မှုတစ်ခုစီအတွက် အထွက်အခြေခံအမည်အသစ်ကို ထားရှိပါ။

လက်ရှိ Juntei သွင်းအားစုများသည် ကဲ့သို့သော အတိုကောက် အညွှန်းများကို အသုံးပြုသည်။ `Comp`, `Filename`, `Args` နှင့် `Attr`. MFT CSV လက်ရှိကိုလည်း လက်ခံတယ်။ `File`, `SN`, `ParentEntryNum`, `ParentSN`, `Type`, `USN`, `LogfileSN` နှင့် `HasADS` headers၊ sequence-number generations တို့ကို ထိန်းကျောင်းပါ။ DOS/ADS ကွဲလွဲမှုတွေက အရင်အတိုင်းပါပဲ။ အဟောင်းများကို တင်ပို့သည့် တံဆိပ်များကို လက်ခံထားဆဲဖြစ်ပြီး၊ `SourceField` အမှန်တကယ်ထည့်သွင်းမှုတွင် စာလုံးပေါင်းကို ထိန်းသိမ်းထားသည်။ Hayabusa input သည်၎င်း၏ကိုယ်ပိုင်ကိုထိန်းသိမ်းထားသည်။ `Computer` လယ်ကွင်း။ ပွဲစဉ်အချိန်တံဆိပ်ကို မပံ့ပိုးပေးသောကြောင့် Boot-sector နှင့် security-descriptor မက်တာဒေတာကို အချိန်မသတ်မှတ်ရသေးသော အစီရင်ခံစာတွင် ထိန်းသိမ်းထားသည်။

## အသစ်သော ဇယားပေါင်းစုံ ခွဲခြမ်းစိပ်ဖြာမှုများ { #newer-multi-table-parsers }

မူရင်း JSON/JSONL သည် ဇယားတစ်ခုစီ၏ အမည်ဖြစ်သည်။ သီးခြားရပ်တည်နေသော CSV အတွက်၊ ဘရောက်ဆာ၊ WebCache နှင့် Outlook အဒက်တာများသည် ၎င်း၏ဇယားကို ကော်လံပုံစံအစီအစဉ်မှ ခွဲခြားသတ်မှတ်ထားသောကြောင့် CSV အား အမည်ပြောင်းခြင်း သို့မဟုတ် အလိုအလျောက်ခွဲခြမ်းစိတ်ဖြာခြင်း၏ ရင်းမြစ်နောက်ဆက်တွဲများကို အသုံးပြုခြင်းဖြင့် အချိန်တံဆိပ်အဓိပ္ပာယ်ကို ပြောင်းလဲမည်မဟုတ်ပါ။ UAL သည် ၎င်း၏ ရှင်းလင်းပြတ်သားသော အချိန်တံဆိပ်တုံးများကို သိမ်းဆည်းထားသည်။ အသုံးပြုခွင့်ကောင်တာများနှင့် မသက်ဆိုင်သော ရက်စွဲပုံစံ စာသားများကို ရက်စွဲများအဖြစ် ခန့်မှန်းမထားပါ။

Outlook ၏ ပိုင်ဆိုင်မှုအတန်းများကို ၎င်းတို့၏ ကြေငြာအမျိုးအစားသည် အချိန်တစ်ခု သို့မဟုတ် အချိန်များစွာ အမျိုးအစားဖြစ်မှသာ ပရိုဂျက်တာဖြစ်သည်။ ရက်စွဲပါရှိသော စာကြောင်းတစ်ခုသည် စာကြောင်းတစ်ခု ကျန်နေသေးသည်။ ထည့်သွင်းထားသော မက်ဆေ့ဂျ်များသည် ၎င်းတို့၏ အကြောင်းအရာ ID များနှင့် မိဘအကိုးအကားများကို သိမ်းဆည်းထားပြီး ပူးတွဲပါဖိုင်ထုတ်ယူသည့်အချိန်များကို သိမ်းဆည်းထားသည့် ပူးတွဲပါအချိန်တံဆိပ်တုံးများအတွက် အစားထိုးမည်မဟုတ်ပါ။ အချိန်မရသေးသော ဖိုင်၊ လက်ခံသူ၊ အဆက်အသွယ် သို့မဟုတ် ပိုင်ဆိုင်မှုအတန်းများသည် မူရင်းထုတ်ပေးမှုနှင့် အချိန်မသတ်မှတ်ရသေးသော အစီရင်ခံစာတွင် ခြေရာခံနိုင်မည်ဖြစ်သည်။

တူညီသော CSV နှင့် JSONL အထွက်အစီအစဉ်များသည် ဤခွဲခြမ်းစိတ်ဖြာခြင်းအတွက် သက်ရောက်မှုရှိသည်။ အသစ်တစ်ခုထည့်သွင်းခြင်းသည် CSV ကော်လံရာပေါင်းများစွာကို ထည့်ထားခြင်းမရှိပါ။ Artifact-specific context သည် `Details` တွင်ရှိနေပါသည်။
