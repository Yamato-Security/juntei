# ประวัติ PowerShell { #powershell-history }

## สิ่งที่ประวัติบันทึกไว้ { #what-the-history-records }

PSReadLine บันทึกบรรทัดคำสั่งที่ป้อนในโฮสต์ PowerShell แบบโต้ตอบ ไฟล์มีข้อความตามลำดับที่บันทึก โดยไม่มีเวลาประทับแยกแต่ละคำสั่ง ประวัติอาจถูกแก้ไข ล้าง ปิดใช้งาน หรือกรอง และไม่ได้พิสูจน์ว่าคำสั่งทำงานสำเร็จ ตรวจสอบการทำงานและเวลากับล็อกเหตุการณ์ PowerShell ข้อมูลเทเลเมทรีของโปรเซส และอาร์ติแฟกต์การทำงานอื่นร่วมด้วย

## ตำแหน่งและการเก็บรวบรวม { #location-and-collection }

ตำแหน่งเริ่มต้นบน Windows สำหรับ Windows PowerShell 5.1 และ PowerShell 7+ คือ:

```text
%APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\<Host>_history.txt
C:\Users\<user>\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt
```

โฮสต์อื่นใช้ชื่อเช่น `Visual Studio Code Host_history.txt` ในไดเรกทอรีเดียวกัน PowerShell บน Linux และ macOS มักใช้ `~/.local/share/powershell/PSReadLine/<Host>_history.txt` การตั้งค่า `HistorySavePath` ของ PSReadLine เปลี่ยนตำแหน่งไฟล์ได้ พาธเริ่มต้นเหล่านี้เป็นสมมติฐานในการค้นหา ไม่ได้ครอบคลุมทุกตำแหน่ง

อินพุตแบบไดเรกทอรีและ `auto-parse` เลือกไฟล์ `<Host>_history.txt` ที่อยู่ในโฟลเดอร์ `PSReadLine` โดยตรงด้วยการค้นหาแบบเรียกซ้ำ และไม่แยกตัวพิมพ์ใหญ่เล็ก ASCII ทั้งสองแบบไม่เลือกไฟล์ `*_history.txt` ใด ๆ ในตำแหน่งอื่น ใช้ `-f` อย่างชัดเจนสำหรับไฟล์ที่เปลี่ยนชื่อหรือสำเนานอกไดเรกทอรี `PSReadLine` หากทำได้ ควรรักษาโครงสร้างโปรไฟล์เดิมเพื่อระบุผู้ใช้

## แยกวิเคราะห์ด้วย Juntei { #parse-with-juntei }

```bash
juntei parse-file powershell-history -d evidence/ -o powershell-history.csv
juntei parse-file powershell-history -f copied-history.txt -t jsonl
```

CSV เป็นรูปแบบไฟล์เริ่มต้น เมื่อใช้ `-t csv`, `-t json` หรือ `-t jsonl` โดยไม่มี `-o` จะเขียนระเบียนไปยัง stdout หากไม่มีทั้งสองตัวเลือกจะแสดงเพียงสรุป JSON เป็นอ็อบเจ็กต์แยกกันที่จัดรูปแบบให้อ่านง่าย ส่วน JSONL มีหนึ่งอ็อบเจ็กต์ต่อบรรทัด เพิ่ม `-C` เพื่อเขียนทับเอาต์พุตที่มีอยู่ พาธนามแฝงที่ชี้ไปยังไฟล์ต้นฉบับจะได้รับการป้องกันไม่ให้ถูกแทนที่

`auto-parse` บันทึกเป็น `ShellHistory/PowerShellHistory.csv` หรือรูปแบบ JSON ที่เลือก รวมถึงกรณีอิมเมจ VHDX/E01 ประวัติไม่เพิ่มเหตุการณ์ให้ `auto-parse -j` หรือ `super-timeline`

## การเข้ารหัสและการจัดการบรรทัด { #encoding-and-line-handling }

- เครื่องหมายลำดับไบต์ UTF-8, UTF-16LE หรือ UTF-16BE กำหนดการเข้ารหัสและถูกลบจากต้นไฟล์ หากไม่มี BOM จะถือว่าอินพุตเป็น UTF-8 เสมอ ไม่มีการคาดเดา UTF-16 ที่ไม่มี BOM อักขระ NUL จะคงไว้และรายงานว่าอาจเกิดความเสียหายด้านการเข้ารหัส
- ลำดับ UTF-8 ที่ไม่ถูกต้องและเซอร์โรเกต UTF-16 ที่ไม่มีคู่จะเปลี่ยนเป็น U+FFFD พร้อมรายงานความเสียหายใน `Problems` ไบต์ UTF-16 ที่เหลือเดี่ยวท้ายไฟล์และข้อผิดพลาดในการอ่านก็ถูกรายงานด้วย โดยเก็บบรรทัดที่อ่านได้ไว้ ตรวจทั้ง `Problems` และล็อกของพาร์เซอร์ก่อนเชื่อถือความครบถ้วน
- ประมวลผลไฟล์แบบสตรีม โดยเก็บอินพุตสูงสุด 1,048,576 ไบต์ต่อบรรทัดจริง ไม่รวม BOM และตัวคั่น LF (CR ก่อน LF นับรวมในขีดจำกัด) บรรทัดที่ยาวกว่าจะถูกตัดที่ขอบเขตอักขระสมบูรณ์ อ่านไบต์ที่เหลือต่อจนหมด และ `Problems` รายงานจำนวนไบต์ที่ละไว้ ขีดจำกัดใช้กับไบต์อินพุตที่เข้ารหัส ไม่ใช่จำนวนอักขระ
- ลบตัวจบบรรทัด LF และ CRLF รวมถึง CR ท้ายบรรทัดที่ไม่มีตัวจบบรรทัด ช่องว่างและแท็บอื่นยังคงอยู่ บรรทัดว่างไม่สร้างระเบียนแต่ยังนับในหมายเลขบรรทัดและยุติชุดบรรทัดต่อเนื่อง บรรทัดที่มีเพียงอักขระช่องว่างยังเป็นระเบียน ข้อผิดพลาดในการอ่านอาจสร้างแถววินิจฉัยว่างเพื่อระบุตำแหน่งที่หยุดอ่าน
- PSReadLine เก็บรายการหลายบรรทัดโดยใส่แบ็กทิกท้ายบรรทัดจริงแต่ละบรรทัดที่มีการต่อเนื่อง บรรทัดยังแยกกันและรักษาแบ็กทิกกับการเยื้องไว้ `EntryStartLine` ชี้ไปยังบรรทัดแรกของชุดต่อเนื่องซึ่งบรรทัดก่อนหน้าลงท้ายด้วยแบ็กทิก ไม่มีการตีความไวยากรณ์เชลล์หรือประกอบคำสั่งขึ้นใหม่ การตัดอาจส่งผลต่อการระบุความต่อเนื่อง ตรวจ `Problems` ก่อนจัดกลุ่มแถวเหล่านี้

## ฟิลด์เอาต์พุต { #output-fields }

| ฟิลด์ | ความหมาย |
|---|---|
| `SourceFile` | พาธสัมพัทธ์กับไดเรกทอรีอินพุตโดยใช้ `/` สำหรับ `-f` มีเพียงชื่อไฟล์ ไม่มีการส่งออกพาธต้นทางแบบสัมบูรณ์ |
| `User` | ชื่อโปรไฟล์ที่อนุมานจากพาธที่เก็บไว้ อินพุตแบบไดเรกทอรีรู้จักโครงสร้าง `Users`/`Documents and Settings` ใต้รากอินพุตด้วย ส่วน `-f` ต้องมีส่วนท้ายพาธโปรไฟล์ PSReadLine ตามปกติ ค่าที่ไม่ทราบเป็นช่องว่างใน CSV และ `null` ใน JSON |
| `ShellHost` | ส่วนหน้าของชื่อไฟล์ก่อน `_history.txt` เช่น `ConsoleHost` ไม่ทราบค่าสำหรับไฟล์ที่เปลี่ยนชื่อจนไม่มีส่วนท้ายนี้ |
| `LineNumber` | หมายเลขบรรทัดจริงเริ่มจาก 1 รวมบรรทัดว่างที่ข้ามไป |
| `EntryStartLine` | บรรทัดจริงแรกของชุดบรรทัดต่อเนื่อง หรือหมายเลขของบรรทัดนี้เอง |
| `Command` | บรรทัดจริงที่ถอดรหัสแล้วโดยไม่มีตัวจบบรรทัด อยู่ภายใต้ขีดจำกัดที่ระบุและการป้องกัน CSV |
| `FileLastWriteTime` | เวลาแก้ไขไฟล์ต้นทางซ้ำในแต่ละแถว **เป็นเมทาดาทาของไฟล์ ไม่ใช่เวลาที่คำสั่งทำงาน** การแยกวิเคราะห์อิมเมจใช้เมทาดาทาต้นทางเดิม ไม่ใช่เวลาคัดลอกไปยังพื้นที่ชั่วคราว |
| `FileSize` | ขนาดไฟล์ต้นทางเป็นไบต์ |
| `Encoding` | `UTF-8`, `UTF-8-BOM`, `UTF-16LE` หรือ `UTF-16BE` |
| `Problems` | ข้อมูลวินิจฉัยความเสียหายและการตัดบรรทัด คั่นด้วยอัฒภาคใน CSV และเป็นอาร์เรย์ใน JSON/JSONL ข้อมูลวินิจฉัยระดับไฟล์ปรากฏในล็อกด้วย |

`FileLastWriteTime` ใช้ UTC ในรูปแบบ ISO 8601 เป็นค่าเริ่มต้น เช่น `2026-10-20T08:46:38.5Z` เฉพาะ `auto-parse` เท่านั้นที่รับ `-Z, --timezone` เพื่อเปลี่ยนออฟเซ็ตที่แสดง คำสั่งเดี่ยว `parse-file powershell-history` ไม่มีตัวเลือกเขตเวลา

ตรวจทุกเซลล์ข้อความ CSV หาส่วนหน้าสูตรสเปรดชีต (`=`, `+`, `-`, `@` รวมรูปแบบเต็มความกว้าง และส่วนหน้าที่ตามหลังช่องว่างหรืออักขระที่มองไม่เห็น/อักขระควบคุมบางชนิด) เซลล์ที่เข้าข่ายและเซลล์ที่ขึ้นต้นด้วยอักขระควบคุมจะถูกเติมอะพอสทรอฟีด้านหน้า จึงอาจเปลี่ยนข้อความคำสั่งและพาธใน CSV ส่วน JSON และ JSONL เก็บข้อความที่ถอดรหัสแล้วโดยไม่มีอะพอสทรอฟีของ CSV แต่ยังใช้การแทนที่ระหว่างถอดรหัสและการตัดเช่นเดิม ใช้ JSONL เมื่อเปรียบเทียบข้อความคำสั่งที่บันทึกไว้ และเก็บไฟล์ประวัติต้นทางไว้เสมอ
