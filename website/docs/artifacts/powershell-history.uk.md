# Історія PowerShell { #powershell-history }

## Що записує історія { #what-the-history-records }

PSReadLine зберігає командні рядки, введені в інтерактивному хості PowerShell. Файл містить текст у порядку збереження, без часових позначок окремих команд. Історію можна редагувати, очищувати, вимикати або фільтрувати; вона не доводить успішного завершення команди. Зіставляйте виконання та його час із журналами подій PowerShell, телеметрією процесів та іншими артефактами виконання.

## Розташування та збирання { #location-and-collection }

Типове розташування у Windows для Windows PowerShell 5.1 і PowerShell 7+:

```text
%APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\<Host>_history.txt
C:\Users\<user>\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt
```

Інші хости використовують у цьому каталозі назви на зразок `Visual Studio Code Host_history.txt`. PowerShell у Linux і macOS зазвичай використовує `~/.local/share/powershell/PSReadLine/<Host>_history.txt`. Параметр PSReadLine `HistorySavePath` може змінити розташування файлу; ці типові шляхи є припущеннями для пошуку, а не вичерпним переліком розташувань.

Вхідний каталог і `auto-parse` рекурсивно вибирають файли `<Host>_history.txt` безпосередньо в папці `PSReadLine`, без урахування регістру ASCII. Довільні файли `*_history.txt` в інших місцях не вибираються. Для перейменованого файлу або копії поза каталогом `PSReadLine` явно використовуйте `-f`. За можливості зберігайте початкову структуру профілю для визначення користувача.

## Розбір за допомогою Juntei { #parse-with-juntei }

```bash
juntei parse-file powershell-history -d evidence/ -o powershell-history.csv
juntei parse-file powershell-history -f copied-history.txt -t jsonl
```

Типовий формат файлу — CSV. З `-t csv`, `-t json` або `-t jsonl` без `-o` записи надходять у stdout. Без обох параметрів відображається лише підсумок. JSON містить окремі форматовані об’єкти; JSONL — один об’єкт на рядок. Додайте `-C`, щоб перезаписати наявний результат; альтернативні шляхи до файлу-джерела захищені від заміни.

`auto-parse` зберігає `ShellHistory/PowerShellHistory.csv` (або вибраний формат JSON), зокрема для образів VHDX/E01. Історія не додає подій до `auto-parse -j` або `super-timeline`.

## Кодування та обробка рядків { #encoding-and-line-handling }

- Позначка порядку байтів UTF-8, UTF-16LE або UTF-16BE визначає кодування й вилучається на початку файлу. Без BOM вхід завжди обробляється як UTF-8. UTF-16 без BOM не вгадується; символи NUL зберігаються та позначаються як можливе пошкодження кодування.
- Некоректні послідовності UTF-8 і непарні сурогати UTF-16 замінюються на U+FFFD, а пошкодження відображаються в `Problems`. Також повідомляються зайвий кінцевий байт UTF-16 і помилки читання; читабельні рядки зберігаються. Перш ніж покладатися на повноту, перевірте `Problems` і журнал парсера.
- Файли обробляються потоково. На фізичний рядок зберігається щонайбільше 1,048,576 вхідних байтів без BOM і роздільника LF (CR перед LF входить до обмеження). Довші рядки обрізаються на межі цілого символу, решта байтів зчитується, а `Problems` повідомляє кількість пропущених байтів. Обмеження стосується закодованих вхідних байтів, а не кількості символів.
- Закінчення рядків LF і CRLF вилучаються, як і кінцевий CR у незавершеному рядку. Інші пробіли й табуляції зберігаються. Порожні рядки не створюють записів, але враховуються в нумерації та завершують ланцюжок продовження; рядки лише з пробільних символів залишаються записами. Помилка читання може створити порожній діагностичний рядок для позначення місця зупинки читання.
- PSReadLine зберігає багаторядкові записи зі зворотною лапкою наприкінці кожного фізичного рядка, що продовжується. Рядки залишаються окремими зі збереженням зворотних лапок і відступів. `EntryStartLine` вказує на перший рядок послідовного ланцюжка, попередні рядки якого закінчуються зворотною лапкою. Синтаксис оболонки не інтерпретується, команди не відновлюються. Обрізання може вплинути на визначення продовжень; перед групуванням таких рядків перевірте `Problems`.

## Поля виводу { #output-fields }

| Поле | Тлумачення |
|---|---|
| `SourceFile` | Шлях відносно вхідного каталогу з `/`; для `-f` — лише назва файлу. Абсолютний шлях джерела не експортується. |
| `User` | Назва профілю, визначена зі збереженого шляху. Вхідний каталог також розпізнає структури `Users`/`Documents and Settings` під коренем входу; `-f` потребує звичного суфікса шляху профілю PSReadLine. Невідомі значення порожні в CSV і мають значення `null` у JSON. |
| `ShellHost` | Префікс назви файлу перед `_history.txt`, наприклад `ConsoleHost`; невідомий для перейменованих файлів без цього суфікса. |
| `LineNumber` | Номер фізичного рядка від 1, включно з пропущеними порожніми рядками. |
| `EntryStartLine` | Початковий фізичний рядок ланцюжка продовження або номер цього рядка. |
| `Command` | Декодований фізичний рядок без закінчення рядка; діють описане обмеження та захист CSV. |
| `FileLastWriteTime` | Час зміни файлу-джерела, повторений у кожному рядку. **Метадані файлу, ніколи не час виконання команди.** Розбір образу використовує початкові метадані джерела, а не час тимчасового копіювання. |
| `FileSize` | Розмір файлу-джерела в байтах. |
| `Encoding` | `UTF-8`, `UTF-8-BOM`, `UTF-16LE` або `UTF-16BE`. |
| `Problems` | Діагностика пошкоджень і обрізання рядків; у CSV розділена крапкою з комою, у JSON/JSONL — масив. Діагностика рівня файлу також потрапляє до журналу. |

`FileLastWriteTime` типово використовує UTC у форматі ISO 8601, наприклад `2026-10-20T08:46:38.5Z`. Лише `auto-parse` приймає `-Z, --timezone` для зміни відображуваного зсуву. Окрема команда `parse-file powershell-history` не має параметра часового поясу.

Кожна текстова клітинка CSV перевіряється на префікси формул електронних таблиць (`=`, `+`, `-`, `@`, включно з повноширинними формами та префіксами після пробілів чи певних невидимих/керівних символів). До відповідних клітинок і клітинок, що починаються з керівних символів, додається початковий апостроф. Це може змінити текст команд і шляхів у CSV. JSON і JSONL зберігають декодований текст без апострофа CSV; заміни під час декодування та обрізання все одно діють. Для порівняння збереженого тексту команд використовуйте JSONL і завжди зберігайте файли-джерела історії.
