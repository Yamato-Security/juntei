# Changes

## 1.0.0 [xxxx/xx/xx]

**Bug Fixes:**

- `check-persistence`: bound recursive environment expansion even when substitutions are empty; derive `HOMEPATH` safely from normalized profile paths; retain Startup findings in sparse collections whose root is named after a non-C drive. (@YamatoSecurity)

- `check-persistence`: prevent Unicode registry text from crashing or indefinitely expanding a scan; restrict hive selection to canonical capture locations; retain readable hives and file checks when the input budget is reached; handle captured/original drive labels and DNS/NetBIOS host aliases; bound PE resource traversal; retain accessibility replacement candidates with damaged metadata and recover malformed registry/BITS text; classify OS-directory targets after resolution. (@YamatoSecurity)

**New Features:**

- `check-persistence` uses a shared worker pool for independent checks, payload metadata, and MFT/EVTX timeline streams. `-T, --threads <N>` chooses the worker count (default: logical CPU count); loaded hives and per-payload metadata are shared, and results, coverage, and timestamp selection remain deterministic. Automatic parsing gives each hunter child one worker within its existing process budget. (@YamatoSecurity)

- `check-persistence`: native Rust port of Hexastrike's PyrsistenceSniper, with 130 offline persistence checks, bundled and custom YAML allow/block profiles, CSV/JSON/JSONL findings, per-check coverage, payload hashes and descriptive signature metadata, and independent MFT/event-log timestamp correlation. Supports mounted Windows volumes, standalone hives and multi-host Velociraptor collections; `auto-parse` saves its findings under each host's `persistence` category. Upstream MIT attribution is retained. (@YamatoSecurity)

- `auto-parse` uses readable, capitalized artifact filenames (`SAM.csv`, `MFT.csv`, `UsnJournal.csv`, `PrefetchTimeline.csv`, etc.) with matching `-logs.txt` names. Amcache tables are `Devices.csv`, `Files.csv`, `Findings.csv`, and `Summary.csv` inside each source directory. JSON/JSONL filenames use the same artifact stems, while category folders and SIEM artifact identifiers retain their established names. (@YamatoSecurity)

- Replace `auto-parse`'s single-file switch with `-j, --json-timeline <FILE>`: create an additional SIEM JSONL dataset while retaining categorized CSV, JSON, or JSONL results. CSV mode uses a native JSONL pass with separate logs; JSON and JSONL reuse existing results. Custom destinations are checked before scanning, exports are committed without truncating previous files, and both manifests describe the additional jobs and output. JSONL provenance fields are unique and authoritative when a parser already supplies them. (@YamatoSecurity)

- `auto-parse` groups each computer's CSV/JSON/JSONL results into `accounts`, `file_and_folder_opening`, `file_existence`, `file_system`, `persistence`, `process_execution`, `registry`, and `security_products`, with `<artifact>-logs.txt` files beside the results in each category. Both manifests record each task's category and new result/log paths. Optional Defender extraction is under `security_products/defender-quarantined`; `-j, --json-timeline <FILE>` writes an additional SIEM JSONL dataset while retaining categorized CSV, JSON, or JSONL results and logs. (@YamatoSecurity)

- Group individual parsers by source type: `parse-ese` (srum), `parse-file` (defender-quarantine, jump-lists, lnk, prefetch), `parse-ntfs` (i30, logfile, mft, usn-journal), and `parse-registry` (including amcache and shimcache). Command menus and artifact subcommands are listed alphabetically. Replaces the former flat command names, shortens command descriptions, and updates `auto-parse`, manifest command paths, examples, and documentation. Individual parser options and formats are preserved. (@YamatoSecurity)

- Defender quarantine extraction also writes readable `.security_descriptor.txt` reports beside preserved binary security streams, with owner/group SIDs, well-known account names, DACL/SACL entries, permission masks, inheritance flags and SDDL. Both `parse-file defender-quarantine --extract` and `auto-parse -x` report damaged or unsupported descriptors without losing the recovered payloads. (@YamatoSecurity)
- `parse-ntfs logfile` command: parses NTFS `$LogFile` with ys-logfile-parser. CSV, JSON and JSONL retain each log record in LSN order, redo and undo filenames and timestamps separately, decoded file records/attributes/index entries, transaction links, inferred targets, journal-write offsets, and optional raw bytes. The adjacent `$MFT` (or `-m`) supplies current paths with sequence numbers respected. `auto-parse` discovers collected logs and writes `LogFile.csv` per computer (numbered siblings for multiple volumes). Includes a detailed artifact guide and real-evidence regression tests. (@YamatoSecurity)
- First version of Juntei, a Windows forensics artifact parser. (@YamatoSecurity)
- `auto-parse` command: discovers one or more Windows systems in a triage collection, identifies each computer from Velociraptor `client_info.json`, the `SYSTEM` hive or its collection directory, and runs every supported parser concurrently. Results are organized by computer and investigative category as CSV, JSON or JSONL; JSON records include `Computer` and `Artifact`, and `-j, --json-timeline <FILE>` creates an additional JSONL dataset for SIEM ingestion with CSV, JSON, or JSONL results. Per-parser text logs and JSON/CSV manifests record the original hostname, unique computer identity, source paths, artifact categories, commands, durations and task status. The terminal results summary includes the output file count and total size in MB. (@YamatoSecurity)
- `parse-registry amcache` command: parses `Amcache.hve` (modern Windows 10/11 and legacy Windows 8/8.1/Server 2012 R2 schemas) with Yamato Security's ys-amcache-parser: inventoried executables with SHA-1, PnP devices, and findings for system binaries outside `System32` and executables in staging directories. One file (`-f`) or every Amcache hive under a directory (`-d`); output to the terminal or saved as text, JSON, JSONL or CSV tables (`-o`, `-t`), with a Hayabusa-style progress bar and results summary. (@YamatoSecurity)
- `parse-ntfs mft` command: parses `$MFT` with Yamato Security's ys-mft-parser (a fork of Omer Ben-Amram's mft crate): a CSV with one row per file name and per alternate data stream, with the parent path, both sets of timestamps, USN, LSN, security ID, flags, name type, reference count, reparse target, object ID, logged utility stream, `Zone.Identifier` contents and the timestomping indicators `SI<FN`, `uSecZeros` and `Copied`, with `--all-times`, `--short-names` and `--cutoff`. `-t ys-mft-parser-csv` (one row per entry: full path with `\` separators and the long names from extension records, flags, sizes, timestamps to 100 ns including the MFT-modified times, alternate data streams) and JSON / JSONL (every attribute and the full path) are the same output as the `ys-mft-parser` command (upstream's `mft_dump`). One file (`-f`) or every `$MFT` under a directory (`-d`), entry ranges (`-r`), resident `$DATA` stream extraction (`-e`), a progress bar over the entries and a summary of in-use, deleted and damaged entries. Damaged or crafted records (a parent-reference loop, an unusable first record, malformed data runs) do not crash the run. With `-x`/`--recover-slack`, the file names left in the slack of FILE records (index entries of a directory whose index moved, earlier names, a reused record's previous occupant) get rows marked `FromSlack`, with the record they were found in, their offset and whether a file in use still has the name (`slack_file_names` in JSON). `-i`/`--include-resident-data` adds the content of resident `$DATA` to the CSV (Base64, hex and ASCII), filtered by `-E`/`--resident-extensions` and `-M`/`--resident-max-size`. `-D`/`--dump-entry` shows one entry in full detail (header, attributes, data runs, slack names, bytes) and `-L`/`--list-directory` lists a directory's contents, in use and deleted, by entry or path. (@YamatoSecurity)
- `parse-file prefetch` command: parses Prefetch files (format versions 17 to 31, Windows XP to 11, including compressed files) with Yamato Security's ys-prefetch-parser (a fork of Samuel Garcés Marín's frnsc-prefetch whose output matches libscca): one CSV row or JSON / JSONL object per file with the executable path, prefetch hash, run count, last 8 run times, volumes, directories and loaded files with NTFS file references, or one record per execution sorted by time (`-T`). Findings for Windows system binaries loaded from outside `System32` (high) and executables run from staging directories (medium). One file (`-f`) or every `*.pf` under a directory (`-d`), with a progress bar and a summary. (@YamatoSecurity)
- `parse-ntfs usn-journal` command: parses the NTFS USN change journal (`$UsnJrnl:$J`) with Yamato Security's ys-usn-journal-parser (a fork of sootmark-usn): every V2/V3 record (V4 range-tracking records in JSON), with the path each record's directory had at the time, rewound from the journal and seeded from the volume's `$MFT` (`-m`, or found next to `$Extend`). CSV, or every field as JSON / JSONL; `--carve` finds records in disk images and unallocated space. One file (`-f`) or every `$J` under a directory (`-d`), a byte progress bar and a summary of record versions, time range, creates / deletes / renames, unresolved paths and damaged data. (@YamatoSecurity)
- `parse-ntfs i30` command: parses NTFS directory indexes (`$I30`) with the `i30` module of Yamato Security's ys-mft-parser: one CSV row or JSON / JSONL object per entry of every INDX record, with the file name, namespace, MFT reference, parent, the four `$FILE_NAME` times to 100 ns, allocated and real size, file attributes and the record's LSN, VCN and offsets, and the entries left in their slack by files deleted or renamed out of the directory: whole entries, `$FILE_NAME`s whose entry header or parent was written over, and copies of entries in use (`CopyOfEntryInUse`, `--no-copies`; `--slack-only` for slack entries alone). Records written in part (a torn update sequence array) are read and reported. One file (`-f`; a disk image or unallocated space is searched for INDX records too) or every `$I30` file under a directory (`-d`), a progress bar and a summary of records, entries in use and in slack, and non-copy names in slack that may belong to deleted or renamed files. (@YamatoSecurity)
- `parse-ese srum` command: parses the System Resource Usage Monitor database (`SRUDB.dat`; tested on Windows 10, 11 and Windows Server 2022) with Yamato Security's ys-srum-parser (a fork of Sootmark's ese and srum crates): every entry of every provider table, with programs, accounts, FILETIME columns and network interface types decoded, as one CSV table per provider (plus `IdentityMap.csv`) or one JSON / JSONL object per entry. Account and Wi-Fi network names from the SOFTWARE hive (`-r`, or found in the same collection), read with a small bounds-checked hive reader. One file (`-f`) or every `SRUDB.dat` under a directory (`-d`), a progress bar and a summary of entries per table, time range, bytes sent and received and the top senders. With `--include-value-state` (JSON / JSONL), how each value was read (`parsed`, `null`, `absent`, `unsupported`, `damaged`) and its bytes. (@YamatoSecurity)
- `parse-file lnk` command: parses Windows shortcuts (`*.lnk`) with Yamato Security's ys-lnk-parser (a fork of Sootmark's shell crate): one CSV row per shortcut (target times, size, attributes and MFT reference, volume or network share, arguments, the target item path, the machine name, MAC address and droids of the tracker block, the extra data blocks present) plus icon, hotkey, known and special folder, Darwin, shim layer, network provider and console code page columns, or every field (target items, property stores, console settings) as JSON / JSONL. ANSI text in the code page of the system that made the link (`--code-page`, e.g. 932). Findings for arguments hidden inside string data that claims more than 260 characters (read as Windows reads it), data appended after the link and shells or script hosts started with arguments. One file (`-f`) or every `*.lnk` under a directory (`-d`), a progress bar and a summary of target drive types, machines, time range and damaged links. (@YamatoSecurity)
- `parse-file jump-lists` command: parses Windows jump lists with Yamato Security's ys-jump-lists-parser (from Sootmark's shell crate's jump list and compound file code, with links read by ys-lnk-parser): automatic jump lists (every `DestList` version, Windows 7 to 11, including files that end inside their last sector) and custom jump lists, as two CSV tables (`AutomaticDestinations.csv` with every `DestList` entry and its link, plus link streams no entry names; `CustomDestinations.csv` with every category's links) and more columns, or every field as JSON / JSONL (the `DestList` header, entries' property stores, the `DestListPropertyStore`, custom categories). Application names from a list of known AppIDs; links left over from an earlier version of a custom list are recovered. One file (`-f`) or every jump list under a directory (`-d`), a progress bar and a summary of applications, machines, last-used range and target drives, with findings for leftover links, unlisted link streams, items staged for a CD or DVD burn and shells or script hosts started with arguments. (@YamatoSecurity)
- `parse-file defender-quarantine` command: parses Microsoft Defender's quarantine (`Quarantine\Entries`, `ResourceData`, `Resources`) with Yamato Security's ys-defender-history-parser: every entry's threat, scan and quarantine time and every resource it quarantined (files, registry keys, services, startup items, scheduled tasks), each matched with its content and resource record, and the quarantined file's MD5, SHA-1 and SHA-256 (computed from the bytes recovered), owner (from its security descriptor) and download origin (`Zone.Identifier`). Every size, CRC and SHA-1 Defender stores is checked; missing, changed or damaged contents and contents no entry holds are reported. One CSV row or JSON / JSONL object per resource, `QuarantineFolder` telling hosts apart. `--extract` writes quarantined files (only when asked, with a warning) using original filenames where available and a final `.quarantined` extension, without execute permission, never over a file holding something else unless `-C`. One entry (`-f`) or every quarantine folder under a directory (`-d`), a progress bar and a summary of entries, resources, threats and problems. (@YamatoSecurity)
- `parse-registry shimcache` command: parses the ShimCache (AppCompatCache) of `SYSTEM` hives with Yamato Security's ys-shimcache-parser (a fork of Security Ronin's shimcache-forensic): every format from Windows XP to 11 (the execution flag of Windows 7 to 11, Windows XP's LRU order, the 32 or 64 bit layout of Vista and 7 from the hive), every control set with `Duplicate` (an entry seen before), the hive's transaction logs (`SYSTEM.LOG1`, `SYSTEM.LOG2`) replayed when it is dirty, also when its base block is damaged (`--no-logs` to read it as it is), and entries recovered from the slack of the cache's value. One CSV row per entry, with the cache format and last write time, flags, data size, machine type, Windows XP's file size and update time, packaged app names, findings, the cache value's registry path and size, and the `SYSTEM\Select` control sets (`IsCurrent`), or every field as JSON / JSONL. One file (`-f`, a hive or an AppCompatCache value on its own) or every `SYSTEM` hive under a directory (`-d`), a progress bar and a summary of caches, entries, executions, time range, damaged entries and findings (system binaries outside `System32`, executables in staging directories). (@YamatoSecurity)
- `parse-registry` command, with one subcommand per registry artifact, reading hives (`SYSTEM`, `SOFTWARE`, `SAM`, `SECURITY`, `NTUSER.DAT`, `UsrClass.dat`, `Amcache.hve`, …) with Yamato Security's ys-registry-parser. `parse-registry read`: one record per value (`default_value` for a key's unnamed value), per key without values or with damage, and, with `--value` and a key filter, per key without that value (`absent_value`), with the host (the computer name of the system's `SYSTEM` hive), hive type, key path and last-write time, the value's type and data decoded (strings, multi-strings as lists, numbers whole and in `value_u64`, binary in hex), its bytes when it doesn't decode or `--raw-data` asks, and a `REG_QWORD` also as a FILETIME with `--qword-as-filetime`. Each record says whether it is allocated or deleted (`--recover-deleted`: keys and values left in free cells, deleted keys' paths rebuilt through their parents) and whether the transaction logs wrote it: a dirty hive gets its logs replayed (next to it, or `--log1` / `--log2`; `--no-logs` to read it as it is). Filters on one key (`--key`, also as `HKLM\SOFTWARE\…` or with `CurrentControlSet`), key paths (`--key-regex`), one value (`--value`), value names and data (`--value-regex`, `--data-regex`, ignoring case so a GUID matches in any case) and last-write times (`--timeline-start`, `--timeline-end`). Damaged keys and values are reported and their siblings still read. One hive (`-f`) or every hive under a directory (`-d`), a progress bar and a summary of hive types, hosts, recovery, keys, values, deleted records and damage. CSV, JSON or JSONL. (@YamatoSecurity)
- `parse-registry services`: the services of `SYSTEM` hives, from the control set in use (`Select\Current`) or every one (`--all-control-sets`), with ys-registry-parser: image path, service DLL (`Parameters\ServiceDll`), start and type (named, with their numbers), delayed start, error control, account, group, and the failure actions decoded from `FailureActions` (reset period, each action's type and delay) with the `FailureCommand`. A value that can't be read or isn't of its type is a problem, an undecodable `FailureActions` keeps its bytes. One hive (`-f`, `--log1`, `--log2`, `--no-logs`) or every `SYSTEM` hive under a directory (`-d`), `--service` for one service, the host of each hive, a summary of services by start type, failure actions and the failure commands they run. CSV, JSON or JSONL. (@YamatoSecurity)
- `parse-registry recentdocs`: Explorer's recent documents in `NTUSER.DAT` hives, with ys-registry-parser: one record per item of `RecentDocs` and of each of its subkeys (one per extension, and `Folder`), in the order of the key's `MRUListEx`, with the item's name, the name of its shortcut in the `Recent` folder (from the shell item), the key's last-write time, and `last_opened` for the most recent item. The user comes from the profile folder the hive is in, else from its shell folders' paths. Items the list names but the key hasn't, values it doesn't name, and values that don't decode are reported. One hive (`-f`, `--log1`, `--log2`, `--no-logs`) or every `NTUSER.DAT` under a directory (`-d`), the host and user of each hive, a summary with each hive's most recent item. CSV, JSON or JSONL. (@YamatoSecurity)
- `parse-registry taskcache`: the Task Scheduler's cache in `SOFTWARE` hives, with ys-registry-parser: one record per action of each task, with its name, GUID, index and lists (`Boot`, `Logon`, `Plain`, `Maintenance`), its `Tree` and `Tasks` keys' times, its actions decoded by their structure (program, arguments and working directory; COM handler class id and data; the context they run in), `Author`, `URI`, and from `DynamicInfo` when it was last registered, last ran and last ran successfully, and its last result. Tasks the Task Scheduler doesn't show are `hidden`: a `Tasks` key without a `Tree` entry, or a `Tree` entry without its security descriptor. One hive (`-f`, `--log1`, `--log2`, `--no-logs`) or every `SOFTWARE` hive under a directory (`-d`), `--task` for one task, the host of each hive, a summary of tasks, actions, hidden tasks and the programs of tasks outside `\Microsoft\`. CSV, JSON or JSONL. (@YamatoSecurity)
- `parse-registry sam`: the local accounts in `SAM` hives, with ys-registry-parser: one record per account with its RID, user name, full name and comments, account control flags (named, with their number), last logon (to the 100 ns and to the second), password last set, expiry, last failed logon (the FILETIMEs kept too), failed and total logon counts, password hint, linked Microsoft account, whether the sign-in screen hides it, its key's and its `Names` entry's times; what disagrees between `F`, `V` and `Names` is reported. Password hashes are not read. One hive (`-f`, `--log1`, `--log2`, `--no-logs`) or every `SAM` hive under a directory (`-d`), `--rid` for one account, the host of each hive, a summary of accounts with their state, last logon and logons, and accounts people made that the sign-in screen hides. CSV, JSON or JSONL. (@YamatoSecurity)
- `parse-registry persistence`: autostart locations in `SOFTWARE`, `SYSTEM`, `NTUSER.DAT` and `UsrClass.dat` hives, with ys-registry-parser's `persistence` module: one record per program, DLL or package with its mechanism and MITRE ATT&CK technique, key, value, data, program and arguments, whether it is enabled, the user and SID of a user hive, and whether it is under `Wow6432Node`. Run keys (`Run`, `RunOnce`, `RunOnceEx`, `RunServices`, `Policies\Explorer\Run`) with `StartupApproved` (disabled entries with the time they were disabled, and entries whose `Run` value is gone), `Winlogon`, `AppInit_DLLs`, `AppCertDlls`, Image File Execution Options and `SilentProcessExit` (enabled as `GlobalFlag` and, for `MonitorProcess`, `ReportingMode` say), `Session Manager` (`BootExecute`, `KnownDLLs`, `PendingFileRenameOperations`), .NET profiler variables, LSA packages and security providers, print monitors, providers and processors, netsh helpers, time providers, Active Setup, `Command Processor` `AutoRun`, the screen saver, logon scripts, app debuggers, and a user's COM servers and `shell\open\command`s with whether they override the machine's registration (from the system's `SOFTWARE` hive). One hive (`-f`, `--log1`, `--log2`, `--no-logs`) or every one of the four under a directory (`-d`), `--all-control-sets`, the host of each hive, a summary of autostarts by mechanism, disabled ones, `StartupApproved\Run` and `Run32` entries without their `Run` value, and overrides of the machine's classes. CSV, JSON or JSONL. Also an `auto-parse` task. (@YamatoSecurity)
- `parse-registry userassist`: the programs and shortcuts users started from Explorer, from UserAssist in `NTUSER.DAT` hives, with ys-registry-parser: one record per item with its `{GUID}` key and kind (`executable`, `shortcut`, …), its name as stored (ROT13) and decoded, its path with a known folder's GUID replaced by the folder's default path, its run count, focus count, focus time and last run (version 5, Windows 7 and later; version 3, Windows 2000 to Vista, its count less 5), and the user's name and SID (from the system's `ProfileList`). Data that doesn't decode keeps its bytes. One hive (`-f`, `--log1`, `--log2`, `--no-logs`) or every `NTUSER.DAT` under a directory (`-d`), the host of each hive, a summary of items by kind, the items run last, and the hives where UserAssist is turned off (`Start_TrackProgs`, `NoInstrumentation`, `NoLog`). CSV, JSON or JSONL. Also an `auto-parse` task. (@YamatoSecurity)
- `parse-registry` commands refuse an output file (`-o`) that is one of the files they read, even with `-C`: the hive, its transaction logs (next to it or given), and the `SYSTEM` and `SOFTWARE` hives of its system, by path, symbolic link or hard link (told apart without opening them, so a write-only input is protected too). An output that can't be told apart from them is not written either. (@YamatoSecurity)
- `parse-registry read --recover-deleted`: deleted keys and values also from the slack of cells in use and the data past the hive bins, and what only the transaction logs kept (the hive before their replay, and each log entry's pages, applied or older than the hive); `allocation_status` says how complete each is (`deleted_complete`, `deleted_partial`, `residual_value_only`, `transaction_log_recovered`), and the new `recovered_from` where it was found (`free_cell`, `cell_slack`, `remnant_data`, `before_replay`, `SYSTEM.LOG1#1234`), each record once. The summary counts recovered keys and values by status. (@YamatoSecurity)
