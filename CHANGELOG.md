# Changes

## 1.0.0 [xxxx/xx/xx]

**New Features:**

- First version of Juntei, a Windows forensics artifact parser. (@YamatoSecurity)
- `parse-amcache` command: parses `Amcache.hve` (modern Windows 10/11 and legacy Windows 8/8.1/Server 2012 R2 schemas) with Yamato Security's ys-amcache-parser: inventoried executables with SHA-1, PnP devices, and findings for system binaries outside `System32` and executables in staging directories. One file (`-f`) or every Amcache hive under a directory (`-d`); output to the terminal or saved as text, JSON, JSONL or CSV tables (`-o`, `-t`), with a Hayabusa-style progress bar and results summary. (@YamatoSecurity)
- `parse-mft` command: parses `$MFT` with Yamato Security's ys-mft-parser (a fork of Omer Ben-Amram's mft crate): a CSV with one row per file name and per alternate data stream, with the parent path, both sets of timestamps, USN, LSN, security ID, flags, name type, reference count, reparse target, object ID, logged utility stream, `Zone.Identifier` contents and the timestomping indicators `SI<FN`, `uSecZeros` and `Copied`, with `--all-times`, `--short-names` and `--cutoff`. `-t ys-mft-parser-csv` (one row per entry: full path with `\` separators and the long names from extension records, flags, sizes, timestamps to 100 ns including the MFT-modified times, alternate data streams) and JSON / JSONL (every attribute and the full path) are the same output as the `ys-mft-parser` command (upstream's `mft_dump`). One file (`-f`) or every `$MFT` under a directory (`-d`), entry ranges (`-r`), resident `$DATA` stream extraction (`-e`), a progress bar over the entries and a summary of in-use, deleted and damaged entries. Damaged or crafted records (a parent-reference loop, an unusable first record, malformed data runs) do not crash the run. (@YamatoSecurity)
- `parse-prefetch` command: parses Prefetch files (format versions 17 to 31, Windows XP to 11, including compressed files) with Yamato Security's ys-prefetch-parser (a fork of Samuel Garcés Marín's frnsc-prefetch whose output matches libscca): one CSV row or JSON / JSONL object per file with the executable path, prefetch hash, run count, last 8 run times, volumes, directories and loaded files with NTFS file references, or one record per execution sorted by time (`-T`). Findings for Windows system binaries loaded from outside `System32` (high) and executables run from staging directories (medium). One file (`-f`) or every `*.pf` under a directory (`-d`), with a progress bar and a summary. (@YamatoSecurity)
- `parse-usn-journal` command: parses the NTFS USN change journal (`$UsnJrnl:$J`) with Yamato Security's ys-usn-journal-parser (a fork of sootmark-usn): every V2/V3 record (V4 range-tracking records in JSON), with the path each record's directory had at the time, rewound from the journal and seeded from the volume's `$MFT` (`-m`, or found next to `$Extend`). CSV, or every field as JSON / JSONL; `--carve` finds records in disk images and unallocated space. One file (`-f`) or every `$J` under a directory (`-d`), a byte progress bar and a summary of record versions, time range, creates / deletes / renames, unresolved paths and damaged data. (@YamatoSecurity)
- `parse-srum` command: parses the System Resource Usage Monitor database (`SRUDB.dat`; tested on Windows 10, 11 and Windows Server 2022) with Yamato Security's ys-srum-parser (a fork of Sootmark's ese and srum crates): every entry of every provider table, with programs, accounts, FILETIME columns and network interface types decoded, as one CSV table per provider (plus `SruDbIdMapTable.csv`) or one JSON / JSONL object per entry. Account and Wi-Fi network names from the SOFTWARE hive (`-r`, or found in the same collection), read with a small bounds-checked hive reader. One file (`-f`) or every `SRUDB.dat` under a directory (`-d`), a progress bar and a summary of entries per table, time range, bytes sent and received and the top senders. With `--include-value-state` (JSON / JSONL), how each value was read (`parsed`, `null`, `absent`, `unsupported`, `damaged`) and its bytes. (@YamatoSecurity)
- `parse-lnk` command: parses Windows shortcuts (`*.lnk`) with Yamato Security's ys-lnk-parser (a fork of Sootmark's shell crate): one CSV row per shortcut (target times, size, attributes and MFT reference, volume or network share, arguments, the target item path, the machine name, MAC address and droids of the tracker block, the extra data blocks present) plus icon, hotkey, known and special folder, Darwin, shim layer, network provider and console code page columns, or every field (target items, property stores, console settings) as JSON / JSONL. ANSI text in the code page of the system that made the link (`--code-page`, e.g. 932). Findings for arguments hidden inside string data that claims more than 260 characters (read as Windows reads it), data appended after the link and shells or script hosts started with arguments. One file (`-f`) or every `*.lnk` under a directory (`-d`), a progress bar and a summary of target drive types, machines, time range and damaged links. (@YamatoSecurity)
- `parse-jump-lists` command: parses Windows jump lists with Yamato Security's ys-jump-lists-parser (from Sootmark's shell crate's jump list and compound file code, with links read by ys-lnk-parser): automatic jump lists (every `DestList` version, Windows 7 to 11, including files that end inside their last sector) and custom jump lists, as two CSV tables (`AutomaticDestinations.csv` with every `DestList` entry and its link, plus link streams no entry names; `CustomDestinations.csv` with every category's links) and more columns, or every field as JSON / JSONL (the `DestList` header, entries' property stores, the `DestListPropertyStore`, custom categories). Application names from a list of known AppIDs; links left over from an earlier version of a custom list are recovered. One file (`-f`) or every jump list under a directory (`-d`), a progress bar and a summary of applications, machines, last-used range and target drives, with findings for leftover links, unlisted link streams, items staged for a CD or DVD burn and shells or script hosts started with arguments. (@YamatoSecurity)
- `parse-defender-quarantine` command: parses Microsoft Defender's quarantine (`Quarantine\Entries`, `ResourceData`, `Resources`) with Yamato Security's ys-defender-history-parser: every entry's threat, scan and quarantine time and every resource it quarantined (files, registry keys, services, startup items, scheduled tasks), each matched with its content and resource record, and the quarantined file's MD5, SHA-1 and SHA-256 (computed from the bytes recovered), owner (from its security descriptor) and download origin (`Zone.Identifier`). Every size, CRC and SHA-1 Defender stores is checked; missing, changed or damaged contents and contents no entry holds are reported. One CSV row or JSON / JSONL object per resource, `QuarantineFolder` telling hosts apart. `--extract` writes the quarantined files (only when asked, with a warning), named by their SHA-1, without execute permission, never over a file holding something else unless `-C`. One entry (`-f`) or every quarantine folder under a directory (`-d`), a progress bar and a summary of entries, resources, threats and problems. (@YamatoSecurity)
- `parse-shimcache` command: parses the ShimCache (AppCompatCache) of `SYSTEM` hives with Yamato Security's ys-shimcache-parser (a fork of Security Ronin's shimcache-forensic): every format from Windows XP to 11 (the execution flag of Windows 7 to 11, Windows XP's LRU order, the 32 or 64 bit layout of Vista and 7 from the hive), every control set with `Duplicate` (an entry seen before), the hive's transaction logs (`SYSTEM.LOG1`, `SYSTEM.LOG2`) replayed when it is dirty, also when its base block is damaged (`--no-logs` to read it as it is), and entries recovered from the slack of the cache's value. One CSV row per entry, with the cache format and last write time, flags, data size, machine type, Windows XP's file size and update time, packaged app names, findings, the cache value's registry path and size, and the `SYSTEM\Select` control sets (`IsCurrent`), or every field as JSON / JSONL. One file (`-f`, a hive or an AppCompatCache value on its own) or every `SYSTEM` hive under a directory (`-d`), a progress bar and a summary of caches, entries, executions, time range, damaged entries and findings (system binaries outside `System32`, executables in staging directories). (@YamatoSecurity)
- `parse-registry` command, with one subcommand per registry artifact, reading hives (`SYSTEM`, `SOFTWARE`, `SAM`, `SECURITY`, `NTUSER.DAT`, `UsrClass.dat`, `Amcache.hve`, …) with Yamato Security's ys-registry-parser. `parse-registry read`: one record per value (`default_value` for a key's unnamed value), per key without values or with damage, and, with `--value` and a key filter, per key without that value (`absent_value`), with the host (the computer name of the system's `SYSTEM` hive), hive type, key path and last-write time, the value's type and data decoded (strings, multi-strings as lists, numbers whole and in `value_u64`, binary in hex), its bytes when it doesn't decode or `--raw-data` asks, and a `REG_QWORD` also as a FILETIME with `--qword-as-filetime`. Each record says whether it is allocated or deleted (`--recover-deleted`: keys and values left in free cells, deleted keys' paths rebuilt through their parents) and whether the transaction logs wrote it: a dirty hive gets its logs replayed (next to it, or `--log1` / `--log2`; `--no-logs` to read it as it is). Filters on one key (`--key`, also as `HKLM\SOFTWARE\…` or with `CurrentControlSet`), key paths (`--key-regex`), one value (`--value`), value names and data (`--value-regex`, `--data-regex`, ignoring case so a GUID matches in any case) and last-write times (`--timeline-start`, `--timeline-end`). Damaged keys and values are reported and their siblings still read. One hive (`-f`) or every hive under a directory (`-d`), a progress bar and a summary of hive types, hosts, recovery, keys, values, deleted records and damage. CSV, JSON or JSONL. (@YamatoSecurity)
- `parse-registry services`: the services of `SYSTEM` hives, from the control set in use (`Select\Current`) or every one (`--all-control-sets`), with ys-registry-parser: image path, service DLL (`Parameters\ServiceDll`), start and type (named, with their numbers), delayed start, error control, account, group, and the failure actions decoded from `FailureActions` (reset period, each action's type and delay) with the `FailureCommand`. A value that can't be read or isn't of its type is a problem, an undecodable `FailureActions` keeps its bytes. One hive (`-f`, `--log1`, `--log2`, `--no-logs`) or every `SYSTEM` hive under a directory (`-d`), `--service` for one service, the host of each hive, a summary of services by start type, failure actions and the failure commands they run. CSV, JSON or JSONL. (@YamatoSecurity)
- `parse-registry recentdocs`: Explorer's recent documents in `NTUSER.DAT` hives, with ys-registry-parser: one record per item of `RecentDocs` and of each of its subkeys (one per extension, and `Folder`), in the order of the key's `MRUListEx`, with the item's name, the name of its shortcut in the `Recent` folder (from the shell item), the key's last-write time, and `last_opened` for the most recent item. The user comes from the profile folder the hive is in, else from its shell folders' paths. Items the list names but the key hasn't, values it doesn't name, and values that don't decode are reported. One hive (`-f`, `--log1`, `--log2`, `--no-logs`) or every `NTUSER.DAT` under a directory (`-d`), the host and user of each hive, a summary with each hive's most recent item. CSV, JSON or JSONL. (@YamatoSecurity)
- `parse-registry taskcache`: the Task Scheduler's cache in `SOFTWARE` hives, with ys-registry-parser: one record per action of each task, with its name, GUID, index and lists (`Boot`, `Logon`, `Plain`, `Maintenance`), its `Tree` and `Tasks` keys' times, its actions decoded by their structure (program, arguments and working directory; COM handler class id and data; the context they run in), `Author`, `URI`, and from `DynamicInfo` when it was last registered, last ran and last ran successfully, and its last result. Tasks the Task Scheduler doesn't show are `hidden`: a `Tasks` key without a `Tree` entry, or a `Tree` entry without its security descriptor. One hive (`-f`, `--log1`, `--log2`, `--no-logs`) or every `SOFTWARE` hive under a directory (`-d`), `--task` for one task, the host of each hive, a summary of tasks, actions, hidden tasks and the programs of tasks outside `\Microsoft\`. CSV, JSON or JSONL. (@YamatoSecurity)
- `parse-registry sam`: the local accounts in `SAM` hives, with ys-registry-parser: one record per account with its RID, user name, full name and comments, account control flags (named, with their number), last logon (to the 100 ns and to the second), password last set, expiry, last failed logon (the FILETIMEs kept too), failed and total logon counts, password hint, linked Microsoft account, whether the sign-in screen hides it, its key's and its `Names` entry's times; what disagrees between `F`, `V` and `Names` is reported. Password hashes are not read. One hive (`-f`, `--log1`, `--log2`, `--no-logs`) or every `SAM` hive under a directory (`-d`), `--rid` for one account, the host of each hive, a summary of accounts with their state, last logon and logons, and accounts people made that the sign-in screen hides. CSV, JSON or JSONL. (@YamatoSecurity)
- `parse-registry read --recover-deleted`: deleted keys and values also from the slack of cells in use and the data past the hive bins, and what only the transaction logs kept (the hive before their replay, and each log entry's pages, applied or older than the hive); `allocation_status` says how complete each is (`deleted_complete`, `deleted_partial`, `residual_value_only`, `transaction_log_recovered`), and the new `recovered_from` where it was found (`free_cell`, `cell_slack`, `remnant_data`, `before_replay`, `SYSTEM.LOG1#1234`), each record once. The summary counts recovered keys and values by status. (@YamatoSecurity)
